## 구현 범위

사용자 요청에 따라 기존 판정과 몸통 기준 2D 특징, 같은 후보의 MediaPipe 추정 3D 특징을 **동일 처리 프레임**에서 비교하도록 연결했습니다. 추가 모델 학습이나 임계값 변경은 없습니다. 기존 자동 규칙 0.3이 최종 자세를 출력하며, 새 2D/3D 분류기·라벨 결합은 아직 연결하지 않았습니다. 따라서 이번 구현만으로 보류 감소나 정확도 개선을 주장하지 않습니다. 기반 스켈레톤 모델은 사전 학습된 모델입니다.

`posture-evidence-0.1`은 특징 계산의 출처·버전이며 분류 모델 버전이 아닙니다. `available`은 계산에 필요한 수치가 있다는 뜻입니다. 관절 정확도·신뢰성 검증 통과를 뜻하지 않으며 `quality_status=not_assessed`입니다.

## 화면에서 확인

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live
```

1. 카메라 또는 저장 영상을 연결합니다.
2. 오른쪽 AI 자세 판정의 **2D·3D 근거 비교**를 펼칩니다.
3. 기존 자세/보류, 2D 특징 계산 여부, 2D+추정 3D 가용 상태를 확인합니다.

기존 자세 판정에는 침대 영역이 필요합니다. 새 몸통 특징 자체는 영역 지정 전에도 계산할 수 있습니다. 화면에는 어깨·골반의 벌어짐, 몸통 방향 어긋남과 추정 깊이 차이 비율을 표시합니다. 결측은 `—`와 사유로 표시하며 0으로 대체하지 않습니다. 3D 미지원 입력, 관절 부족, 여러 후보의 대상 불확실, 추적 보류, 처리 실패를 구분합니다. 입력 중단·전환 시 이전 프레임의 비교값을 현재 값으로 표시하지 않습니다.

## 특징과 좌표의 의미

어깨·골반 각 쌍의 중점을 잇는 방향을 몸통 축으로 놓고, 그 길이를 L로 사용합니다. 관절 좌우 차이 벡터를 d, 단위 몸통 축을 t라고 하면 다음과 같습니다.

| 값 | 계산 | 해석과 한계 |
|---|---|---|
| 벌어짐 `transverse` | ‖d − (d·t)t‖ / L | 몸통 축에 수직인 상대 폭. 가림·관절 겹침·원근 변화의 영향도 받음 |
| 어긋남 `axial` | \|d·t\| / L | 몸통 축 방향 차이의 크기. 절댓값이므로 좌우 방향 정보는 없음 |
| 선 사이 각도 | 어깨선·골반선의 방향 부호를 무시한 0~90° 각 | 점이 겹쳐 선을 정의할 수 없으면 결측 |
| 추정 깊이 차이 비율 | (좌관절 z − 우관절 z) / 3D 관절 간 거리 | 모델 좌표의 부호 있는 깊이 성분. 침대 기준 실제 높이·누운 방향 라벨이 아님 |
| 추정 몸통 법선 | 어깨선 × 몸통 축의 단위 벡터 | 모델 축에서만 해석. 침대·중력 방향과 정합하지 않았으므로 바로 자세명으로 변환하지 않음 |

2D는 영상 픽셀에서 계산합니다. 화면 내 평행 이동·회전·동일 비율 확대/축소에 대한 수학적 성질을 모의 좌표로 검사했습니다. 실제 카메라 시점 변화, 원근 투영, 잘못된 관절 추정에 불변인 것은 아닙니다. 현재 자동 규칙도 일부 길이 비율을 사용하며, 이번 작업은 성분 분해와 기록·비교 경로를 추가한 것입니다.

3D는 MediaPipe 원본 `sdk_landmarks.world`의 어깨 11/12, 골반 23/24를 사용합니다. 2D 공통 COCO 인덱스를 3D 인덱스로 오용하지 않도록 어댑터 관절 정의와 원본 대응을 검사하고 `candidate_id`로 같은 후보를 찾습니다. 이 좌표는 단안 모델이 추정한 미터 단위·골반 중점 원점의 좌표이며 실제 거리 센서의 측정값이 아닙니다. 카메라/침대 축 보정, 다중 시점 삼각측량, 두 카메라의 3D 결합은 수행하지 않습니다.

원본 image/world의 visibility·presence는 별도 보존합니다. 임의 점수 임계값으로 가용성을 정확성으로 바꾸지 않습니다. 좌표가 유한하고 계산 가능해도 틀린 스켈레톤일 수 있습니다. 대상 연결은 기존 잠정 추적 수준이고 실제 동일인 검증을 뜻하지 않습니다.

## 기록과 CSV 내보내기

기존 측정 시작/종료 버튼을 사용하면 `manifest.json`에 `posture_evidence_profile`, `live_frames.jsonl`의 각 처리 프레임에 `posture_evidence`가 기록됩니다. 선택적 영상 녹화 여부와 독립적입니다. 실제 수신 시각·clock·프레임·후보 ID 및 기존 판정과 연결하며 목표 자세·정답·외부 센서 결과를 특징 입력으로 사용하지 않습니다.

종료한 **실시간 작업실 측정 폴더**를 지정해 내보냅니다. `--run`은 작업실에 표시된 측정 기록 경로로 바꾸고 `--output`에는 아직 없는 폴더를 사용합니다. 이 명령은 오프라인 `run`의 결과 폴더에는 적용하지 않습니다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose posture-evidence --run "<측정 기록 폴더>" --output "data/posture_comparison_01"
```

- `features.csv`: UTF-8 BOM, 처리 프레임당 한 행. 기존 판정/보류 사유와 2D·3D 특징·결측 사유를 같은 행에 저장합니다. 결측 칸은 비웁니다.
- `summary.json`: 특징 버전, 원본 기록 해시, 프레임 수와 가용/보류 집계, CSV 해시를 저장합니다. 정확도는 계산하지 않습니다.

원본 기록을 먼저 검증하고 원본 관절에서 특징을 재계산합니다. 새 기록의 저장 특징이 재계산값과 다르면 무결성 검사를 거부합니다. 새 필드가 없던 기존 기록도 검증·내보내기 가능하며, 당시 분류기의 호환 검사를 유지합니다. 원본 폴더 내부 출력과 기존 출력 덮어쓰기는 거부하고 원본은 수정하지 않습니다. CSV와 원본에 사람의 관절·시간 정보가 있으므로 GitHub에 올리지 않습니다.

## 검증 및 다음 판단

모의 SDK 좌표로 같은 후보 대응, 회전/크기 변환, 결측·퇴화·비유한 값 처리, 목표/정답/센서 독립성, 기록 재계산과 변조 거부, 이전 기록 호환 및 CLI CSV 출력을 검사했습니다. 전체 개발 검사 180개를 통과했습니다. Chromium 브라우저는 모의 입력으로 3D 유무·몸통 결측·입력 전환·다중 보기·입력 제거와 390/1440/2560px 너비를 확인했고 JavaScript 오류가 없었습니다. wheel에 새 모듈·현재 HTML이 포함되는 것도 확인했습니다. 실제 모델의 침대 영상, Windows 장치, 사람/세션별 분류 정확도 검증은 별도입니다.

다음은 동일 프레임의 실제 자세와 가림·카메라 조건을 별도로 확인하고, 이 특징이 바로 누움·옆으로 누움 구분에 유용한지 비교하는 단계입니다. 앉음·서 있음·엎드림·전환을 함께 확인해야 잘못된 누움 확정을 평가할 수 있습니다. 그 근거로 2D 규칙과 3D 보조 사용 조건을 설계하고 정확도·보류율을 함께 비교합니다. 검증 전 수치 임계값이나 3D 우선순위를 확정하지 않습니다.

공식 좌표 정의: [MediaPipe Pose Landmarker Python](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python). 영상 내 정규화 z와 world 좌표 z는 단위가 다르며, 이번 3D 특징에는 world 좌표만 사용합니다.
