## 1. 프로젝트에 맞춘 선택 기준

이 프로젝트의 카메라 AI는 침대 위 자세·움직임을 **독립적으로 분석**하고, 외부 ToF·mmWave 결과와 동일 시간대에 비교하는 보조 검증 시스템입니다. 최종 비교 범위는 외부 개발자 확인 전입니다.

| 기존 프로젝트 조건 | 기술 선정에 주는 의미 |
|---|---|
| 통제된 침대 환경 우선 | 일반 벤치마크 순위보다 실제 설치 각도에서의 관절 추출 가능성을 먼저 확인 |
| 잠정 자세: 누움·옆으로 누움·걸터앉음·일어남 | 누운 자세뿐 아니라 가장자리·이탈·복귀 영상도 비교 자료에 포함 |
| 자세·점유 상태·이벤트 분리 | 관절 모델만 선택해서는 전체 기능이 완성되지 않음 |
| 카메라와 외부 센서의 독립성 유지 | 외부 센서 예측이나 목표 자세를 카메라 분류 입력으로 사용하지 않음 |
| Windows 기준 논의, PC·카메라 미정 | GPU 필수 여부·설치 가능성·전체 처리 지연은 실제 장비에서 확인 |
| 스마트폰 카메라 입력은 후보 | Android/iPhone, USB/Wi-Fi 입력 품질과 지연을 모델 성능과 분리해 평가 |
| 이불 대응·스마트폰 웹 원격 제어는 추가 검토 | 열화상·압력 융합 등을 초기 필수 사양으로 올리지 않음 |

좌·우 옆누움 세분화와 엎드림은 확정된 초기 라벨이 아닙니다. 기존 [결정 기록](DECISIONS.md)을 기준으로 외부 센서 사양과 함께 정합니다.

### 근거 표시 방법

- **공식 기능 확인:** 공식 문서/저자 코드에 기능이 명시됨. 우리 장비 실행 확인은 아님.
- **일반 과제 실험:** 논문에서 일반 자세 데이터로 평가함. 침대·이불 성능으로 전환하지 않음.
- **침대 과제 실험:** 특정 침대 데이터·센서·촬영 조건에서 평가함. 우리 환경 재현은 아님.
- **적용 제안:** 문헌과 프로젝트 조건을 바탕으로 제안한 구현·기대 효과.
- **자체 검증:** 실제 프로젝트 영상·장비·정답으로 측정한 결과. 현재 모든 후보가 미완료.

## 2. 기술 종류를 구분하는 방법

스켈레톤은 영상에서 추정한 신체 기준점을 연결한 표현입니다. 뼈를 직접 촬영한 결과가 아닙니다.

| 분류 축 | 종류 | 구분 이유 |
|---|---|---|
| 입력 장비 | RGB, 깊이, 다중 카메라, 열화상, 압력맵 | 같은 모델 이름이어도 입력과 학습 조건이 다르면 비교 대상이 달라짐 |
| 관절 획득 방식 | 사람 영역을 찾고 관절 추정, 관절 후보를 찾고 사람별 연결, 사람·관절 공동 예측 | 검출 실패와 관절 추정 실패, 전체 처리 비용을 구분 |
| 출력 차원 | 2D 영상 좌표, 단안 추정 3D, 보정된 다중 시점 3D | 추정 깊이와 실제 표면 거리 측정을 구분 |
| 후속 분석 | 자세 분류, 침대 상대 위치, 시계열·이벤트 | 관절 추출기와 최종 자세/이벤트 모델을 구분 |

MediaPipe는 프레임워크 이름이기도 하므로 여기서는 **MediaPipe Pose Landmarker**를 비교 대상으로 지정합니다. MMPose는 도구 모음이고 RTMPose는 그 안에서 사용할 수 있는 모델입니다. SLP는 데이터셋입니다.

## 3. 후보 선택 요약

아래의 부담·활용도는 프로젝트 설계 관점의 정성적 판단입니다. 비용 견적이나 실행 결과가 아닙니다.

| 후보 | 주된 역할 | 기대 강점 | 도입 부담/핵심 확인점 | 제안 위치 |
|---|---|---|---|---|
| MediaPipe Pose Landmarker | RGB 관절 추정·추적 | 측정 흐름을 빠르게 구성, 33개 기준점 | 누움·측면의 검출 실패, 추정 3D 해석 | 우선 비교 |
| YOLO Pose | 사람 검출·2D 관절 추정 | 통합 출력, 사용자 데이터 학습 경로 | 관절 라벨 비용, 모델 크기별 지연 | 우선 비교 |
| RTMPose/MMPose | 2D 관절 추정·실험 | 설정별 비교·추가 학습 | 검출기를 포함한 구성·설치·지연 | 우선 비교 |
| MoveNet | 경량 2D 관절 추정 | 속도 중심 대안 | 17개 기준점으로 필요한 특징 확보 여부 | 경량 대안 |
| HRNet | 관절 히트맵 추정 | 좌표 품질·침대 연구 재현 비교 | 모델/검출 비용, 별도 학습 | 연구 비교 |
| OpenPose | 다인 2D 관절 및 선택적 3D | 기존 연구 연결, 부위별 출력 | 실행 환경·연산량, 다인 기능의 필요성 | 보조 비교 |
| 단안 3D 추정 | 영상/2D에서 3D 추정 | 추가 카메라 없이 공간 특징 후보 | 학습 환경 차이, 절대 위치·깊이 오해 | 필요 시 확장 |
| 깊이 카메라 | 표면 거리+관절 추정 | 공간 위치 단서 | 장비·정렬·가림·신체 추적 모델 | 장비 확장 |
| 다중 카메라 | 시점 결합·3D 복원 | 한 시점의 가림 보완 | 설치 공간·동기화·보정 | 장비 확장 |
| 열화상 | 열 패턴으로 침대 관절 추정 | 가시광 조명 없는 조건 연구 | 장비·열 전달·전용 학습 | 이불/야간 후속 연구 |
| 압력맵·센서 융합 | 접촉 정보·상보 정보 결합 | 시각 정보 부족 보완 | 추가 장비·학습·독립 비교 목적 | 별도 연구 |

**첫 비교 제안:** MediaPipe·YOLO Pose·RTMPose를 같은 저장 영상에 적용하고 MoveNet을 경량 대안으로 유지합니다. 기존 아키텍처의 후보 방향을 유지한 것이며 채택 결정이 아닙니다.

## 4. RGB 기반 관절 추정 후보

각 후보의 “구현·기대 이점”은 적용 제안입니다. 모든 후보에서 우리 침대 환경의 성능은 미검증입니다.

### 4.1 MediaPipe Pose Landmarker / BlazePose 계열

**어떤 기술인가:** 사람/자세 영역 검출과 랜드마크 추정을 연결합니다. 33개 신체 기준점, 영상 좌표와 추정 3D world 좌표를 제공합니다. Python·Web 등의 공식 구현 안내가 있습니다. [S1]

- **장점:** 입력·추정·화면 표시·기록을 연결하는 초기 측정기를 구성하기 좋습니다. 발뒤꿈치·발끝 등 COCO 17점에 없는 기준점도 있습니다.
- **단점/한계:** 가려진 관절과 누운 자세에서의 검출 가능성을 별도 확인해야 합니다. 좌표가 출력됐다는 사실만으로 정확한 관측이라고 판단할 수 없습니다.
- **구현 방법:** 카메라/영상 프레임과 시각 전달 → Pose Landmarker → 원본 좌표·가시성·결측 상태 저장 → 공통 특징과 분류기로 전달.
- **기대 이점:** 데이터 수집·오버레이·정지 구간 떨림 분석 등 전체 측정 흐름을 먼저 시험할 수 있습니다.
- **선택 조건:** 핵심 자세에서 필요한 관절을 안정적으로 얻고 실제 PC에서 허용 지연을 충족하면 기본 모델 후보로 유지합니다.
- **검증 근거:** 공식 기능 확인. 기존 공식 품질 평가는 Yoga·Dance·HIIT, 카메라에서 2–4m의 단일 인물 조건이며 침대 전용 평가가 아닙니다. [S2]

**좌표 주의:** world 좌표도 단안 영상에서 얻은 모델 추정입니다. 침대/방 기준 절대 위치나 깊이 센서의 표면 거리로 대체하지 않습니다.

### 4.2 YOLO Pose

**어떤 기술인가:** 사람별 영역과 신체 키포인트를 함께 출력하는 계열입니다. Ultralytics의 기본 사람 자세 모델은 COCO 17점 구성을 사용하고 사용자 데이터 학습·모델 내보내기를 지원합니다. 버전·크기·가중치를 고정해 비교해야 합니다. [S3]

- **장점:** 검출 결과와 관절 결과를 함께 관리할 수 있고, 자체 데이터 추가 학습 경로가 문서화되어 있습니다.
- **단점/한계:** 일반 데이터의 사전학습 성능이 누운 자세 성능을 보장하지 않습니다. 모델 크기에 따른 메모리·속도 차이와 관절 라벨 작성 비용이 있습니다.
- **구현 방법:** 사전학습 가중치로 같은 영상 평가 → 실패 자세 수집 → 사람 영역·관절 라벨 검수 → 필요한 경우 추가 학습 → 분리한 시험 자료로 재평가.
- **기대 이점:** 우리 카메라 시점과 자세에 맞춘 관절 추정기 개선을 시도할 수 있습니다.
- **선택 조건:** 사전학습 모델이 충분하면 그대로 사용하고, 실패 패턴이 반복되며 라벨 확보가 가능하면 추가 학습 후보로 유지합니다.
- **검증 근거:** 공식 기능·학습 형식 확인. 침대 성능 개선 폭은 미확인입니다. [S3][S4]

**학습 구분:** “옆으로 누움” 라벨은 자세 분류 학습용입니다. 관절 추정기 학습에는 사람 영역·키포인트 좌표 등의 라벨이 필요합니다. [S4]

### 4.3 RTMPose / MMPose

**어떤 기술인가:** RTMPose는 실시간 2D 자세 추정 모델이며, 원 논문은 사람 검출 후 사람별 관절을 추정하는 top-down 구성을 사용합니다. MMPose는 여러 모델의 실행·학습·평가 도구 모음입니다. [S5]

- **장점:** 모델·학습·평가 설정을 명시해 비교 실험을 구성하기 좋습니다.
- **단점/한계:** 검출기·관절 모델·배포 런타임을 포함해 환경을 구성해야 합니다. 앞단의 사람 검출 실패도 최종 성능에 영향을 줍니다.
- **구현 방법:** 실제 사람 검출기 → RTMPose → 원본 영상 좌표로 복원 → 공통 저장/분류 경로. 고정 영역을 주는 실험은 별도 조건으로 기록합니다.
- **기대 이점:** 동일 평가 체계로 모델과 추가 학습 설정을 비교하고 실패 원인을 검출 단계/관절 단계로 나눌 수 있습니다.
- **선택 조건:** 설치·실행 가능성과 전체 지연을 확인한 뒤 관절 누락·자세 분류 성능의 실질적 이득으로 판단합니다.
- **검증 근거:** 일반 과제 실험. 논문의 COCO 계열 성능을 침대 정확도로 사용하지 않습니다. [S5]

**영역 주의:** 침대 전체를 잘라 넣는 것과 모델이 기대하는 사람 중심 영역은 같지 않습니다. 침대 밖 이탈·복귀 경로가 잘리지 않게 전체 경로도 시험합니다.

### 4.4 MoveNet

**어떤 기술인가:** 17개 기준점을 추정하는 모델입니다. 공식 SinglePose 안내에서 Lightning은 지연 시간, Thunder는 정확도를 중시합니다. [S6]

- **장점:** 경량 실행과 간단한 관절 구성의 비교 후보입니다.
- **단점/한계:** 발끝 같은 추가 기준점은 기본 17점에 없습니다. 저사양 장치의 실제 속도나 침대 정확도를 이름만으로 확정할 수 없습니다.
- **구현 방법:** 두 변형을 같은 영상에 적용 → 공통 관절로 변환 → 같은 분류·품질 평가 경로에 연결.
- **기대 이점:** 단순 자세 분류에 충분한 정보를 더 낮은 실행 부담으로 얻을 수 있는지 확인합니다.
- **선택 조건:** 주요 자세의 품질을 유지하면서 실제 장비의 지연·자원 사용이 유리할 때 채택 후보로 올립니다.
- **검증 근거:** 공식 기능 확인. 우리 침대에서 Lightning/Thunder의 우열은 미확인입니다. [S6]

### 4.5 HRNet

**어떤 기술인가:** 고해상도 특징 경로를 유지하며 여러 해상도의 정보를 반복 결합해 관절 히트맵을 추정하는 구조입니다. 기본 연구는 COCO·MPII에서 평가했습니다. [S7]

- **장점:** 공간적 좌표 품질 비교와 관련 침대 연구의 기반 모델 검토에 유용합니다.
- **단점/한계:** 모델 크기·입력 크기·검출 방식에 따라 비용이 달라집니다. 고해상도 특징이 이불 가림을 해결한다는 뜻은 아닙니다.
- **구현 방법:** 사람 영역 획득 → HRNet → 히트맵에서 좌표 복원 → 공통 평가. 필요하면 침대 데이터로 학습합니다.
- **기대 이점:** 실시간 후보와 비교해 좌표 품질 향상이 실제 자세/이벤트 성능으로 이어지는지 확인할 수 있습니다.
- **선택 조건:** 지연 예산을 만족하면서 의미 있는 품질 개선이 있거나 침대 연구 재현이 목적일 때 검토합니다.
- **검증 근거:** 일반 과제 실험. 별도의 침대 센서 융합 연구가 HRNet 기반 모델을 사용했습니다. 그 결과는 해당 학습·입력 조합의 결과입니다. [S7][S12]

### 4.6 OpenPose

**어떤 기술인가:** 관절 후보와 신체 부위 연결 정보를 이용하는 다인 자세 추정 기술입니다. 공식 구현은 몸·발, 손, 얼굴 및 다중 카메라 삼각측량 기능을 제공합니다. [S8]

- **장점:** 기존 연구 비교와 부위별 좌표 추출에 활용할 수 있습니다.
- **단점/한계:** 사용하는 모듈·장비에 따라 실행 부담이 달라집니다. 다인 기능이 단일 침대 환경의 이점으로 바로 이어지지는 않습니다.
- **구현 방법:** 초기에는 필요한 몸 관절만 활성화 → 저장 영상의 좌표 추출 → 같은 지표로 다른 후보와 비교.
- **기대 이점:** OpenPose를 사용한 기존 연구와 연결하고 다른 사람이 화면에 들어오는 조건을 시험할 수 있습니다.
- **선택 조건:** 기존 연구 재현이나 추가 부위 추적이 필요할 때 비교 후보로 둡니다.
- **검증 근거:** 공식 기능 확인. 몸 관절 수와 손·얼굴을 합한 전체 기준점 수를 혼합하지 않습니다. [S8]

## 5. 3D 및 센서 확장 후보

이 절은 추가 요구가 생길 때 검토할 대안입니다. 장비 선정·구매 제안이나 초기 필수 구현 결정이 아닙니다.

### 5.1 단일 카메라 기반 3D 추정

- **기술:** RGB 또는 연속 2D 관절에서 학습 모델로 3D 자세를 추정합니다. VideoPose3D는 이 방식의 연구 구현 예입니다. [S9]
- **장점:** 추가 카메라 없이 공간적 신체 특징을 얻을 가능성이 있습니다.
- **단점:** 2D 오류·학습 환경 차이·깊이 모호성이 영향을 줍니다. VideoPose3D 예시는 기준 관절 상대 좌표이며 전체 이동 경로를 직접 추정하지 않습니다.
- **구현 제안:** 신뢰할 수 있는 2D 좌표 시계열 → 관절 정의 변환 → 3D 추정 → 2D 특징 대비 추가 이득 평가.
- **프로젝트 이점:** 몸통 방향·굽힘 특징이 자세 구분에 도움이 되는지 시험할 수 있습니다. 이탈 위치 정보는 별도로 유지합니다.
- **검토 조건:** 2D만으로 해결되지 않는 오류가 있고, 그 오류를 3D 특징이 줄이는지 확인할 때.
- **근거·제한:** VideoPose3D 공식 임의 영상 추론은 연구용 참고 구현이며 카메라 조건 차이를 경고합니다. 저장소는 보관 상태입니다. 즉시 적용할 완성형 제품으로 취급하지 않습니다. [S9]

### 5.2 깊이 카메라

- **기술:** 관측 표면까지의 거리 영상에 신체 추적 모델을 적용하거나 RGB 관절과 결합합니다. Azure Kinect Body Tracking은 구현 사례이며 장비 구매 추천은 아닙니다. [S10]
- **장점:** 영상 평면 외의 거리 정보를 사용할 수 있습니다.
- **단점:** 장비·깊이 품질·RGB 정렬·누운 자세용 신체 모델을 확인해야 합니다. 가려진 관절 위치에서 읽은 깊이는 이불 표면일 수 있습니다.
- **구현 제안:** 동기화 RGB/깊이 → 좌표 정렬과 유효 깊이 확인 → 관절/표면 정보 구분 → 침대 관계 분석.
- **프로젝트 이점:** 신체 들림이나 공간적 위치 단서가 걸터앉음·자세 변화 구분을 보완하는지 시험할 수 있습니다.
- **검토 조건:** RGB의 실패 원인이 공간 정보 부족이고 추가 장비가 허용될 때.
- **근거·제한:** 이불의 표면 형태가 같아도 내부 사지 위치가 다를 수 있다는 모호성이 침대 논문에 설명되어 있습니다. 깊이 센서도 관절 자체를 직접 측정하지 않습니다. [S11 §2.1]

### 5.3 다중 카메라

- **기술:** 동기화된 여러 시점의 관절과 보정 정보를 삼각측량해 3D를 복원합니다. OpenPose 3D 모듈이나 aniposelib의 보정·삼각측량 기능이 구현 참고가 됩니다. [S8][S13]
- **장점:** 한 방향에서 가려진 부위를 다른 방향에서 관측할 가능성이 생깁니다.
- **단점:** 좁은 실험 공간, 시간 동기화, 렌즈/위치 보정, 동일 인물·관절 대응이 필요합니다. 모든 시점에서 가려지면 직접 복원할 수 없습니다.
- **구현 제안:** 위쪽/측면 등 설치 가능 시점 조사 → 보정·동기화 → 각 시점 2D 추정 → 대응·삼각측량 → 재투영 오류 확인.
- **프로젝트 이점:** 측면 누움의 겹친 팔다리와 이탈 방향의 시야 부족을 보완할 가능성이 있습니다.
- **검토 조건:** 단일 시점의 가림이 핵심 실패 원인이고 설치 공간·운영 부담을 감당할 수 있을 때.
- **근거·제한:** Anipose는 동물 행동 추적용으로 소개되는 도구입니다. 독립 기하 모듈 활용 제안이지 침대 사람 인식 성능의 증거가 아닙니다. [S13]

### 5.4 열화상(LWIR)

- **기술:** 열 분포로 신체 자세를 추정합니다. UCITD 연구는 이불 접촉 부위로 전달된 열 패턴을 이용합니다. 근적외선 야간 카메라와 구분하며 이불 투시가 아닙니다. [S11 §2.2]
- **장점:** 가시광 조명이 없는 조건에서 활용할 정보가 있습니다.
- **단점:** 열화상 장비·전용 학습이 필요하고 덮개 특성·열 전달 상태에 영향을 받습니다.
- **구현 제안:** 열화상 수집·관절 라벨 → 침대 전용 모델 학습 → 안정 자세와 전환 구간을 분리해 평가.
- **프로젝트 이점:** 이불/야간 대응을 별도 목표로 확장할 때 연구 근거가 됩니다.
- **검토 조건:** 이불·야간 요구가 확정되고 RGB만으로 충족하기 어려울 때.
- **근거·제한:** 인용 연구는 바로 누움·좌/우 옆누움, 천장 카메라, 덮개 조건 변경 후 약 10–20초 대기한 수집 조건입니다. 빠른 뒤척임·엎드림·임의의 두꺼운 이불까지 검증한 것으로 해석하지 않습니다. [S11 §4.1]

### 5.5 압력맵 및 다중 센서 융합

- **기술:** 매트 접촉 압력 분포로 자세를 추정하거나 깊이·열화상 등과 특징을 결합합니다. [S12]
- **장점:** 조명·시각적 가림과 다른 종류의 단서를 제공할 수 있습니다.
- **단점:** 비접촉 신체 부위의 정보가 부족할 수 있고 센서·보정·동기화·학습 비용이 추가됩니다.
- **구현 제안:** 별도 연구 경로에서 동시 수집 → 입력별 특징 추출 → 융합 → 동일 조건의 단일 입력과 비교.
- **프로젝트 이점:** 영상만으로 구분하기 어려운 자세를 접촉·거리·열 패턴으로 보완하는지 시험할 수 있습니다.
- **검토 조건:** 독립 카메라 비교와 구별되는 별도 융합 연구를 진행하기로 결정했을 때.
- **근거·제한:** 침대 HRNet 융합 연구에서 성능 개선 사례가 있지만 모든 센서 조합·모델에 일반화할 수 없습니다. [S12]

**독립성 경계:** 비교 대상인 외부 ToF·mmWave의 예측/측정값을 카메라 AI 입력에 넣지 않습니다. 그렇게 하면 현재 프로젝트가 의도한 독립 결과 비교가 달라집니다. 향후 융합 실험은 별도 결과와 실험 이름으로 관리해야 합니다.

## 6. 관절 추정 이후에 필요한 구현

아래는 기존 [아키텍처](ARCHITECTURE.md)를 후보 비교 관점으로 구체화한 제안입니다.

| 처리 단계 | 입력 → 출력 | 구현 시 주의 |
|---|---|---|
| 영상 입력 | 실시간/저장 영상 → 프레임·시각 | 촬영 시각·수신 시각·출력 시각 구분 |
| 관절 어댑터 | 모델 원본 → 원본 좌표·공통 관절·품질 상태 | 관절 정의·좌우·좌표 범위와 결측 보존 |
| 자세 분류 | 관절 특징 → 잠정 자세/불확실 | 목표 자세·외부 센서 예측 입력 금지 |
| 침대 관계 | 영상 위치·침대 영역 → 가장자리/안팎 관계 | 몸 중심 정규화만으로 위치를 지우지 않음 |
| 시간 분석 | 연속 자세·위치 → 이탈/복귀 등 이벤트 | 미검출을 이탈로 단정하지 않음 |
| 결과 비교 | 두 독립 결과 → 일치도·시점 차이 | 일치도를 정확도로 해석하지 않음 |

**후속 모델 후보:** 각도·상대 거리 등을 사용하는 규칙/SVM/RF/MLP와 상태 전이 규칙을 기준선으로 만들 수 있습니다. 데이터와 실패 원인이 확인되면 LSTM/TCN·ST-GCN 등을 비교합니다. 이들은 영상에서 관절을 찾는 앞단 모델과 역할이 다릅니다. 상세 근거는 [시계열·행동 논문](SKELETON_TECHNOLOGY_PAPERS.md)을 참고합니다.

**원본/보정 분리:** 원본 좌표, 신체 기준 정규화 좌표, 침대 상대 위치를 함께 보존합니다. 필터·보간 결과는 실제 관측과 구분하고 평활화로 생긴 지연도 평가합니다. 신뢰도·가시성 점수의 의미와 범위가 모델마다 다르므로 동일 숫자 임계값이 동일 품질을 뜻한다고 가정하지 않습니다.

## 7. 후보를 실제로 고르는 실험 순서

### 7.1 비교 자료 준비

1. 같은 저장 영상에 잠정 자세와 자세 전환·침대 이탈·복귀를 포함합니다.
2. 사람의 몸이 잘 보이는 통제 조건부터 시작하고 시점·거리·조명을 기록합니다.
3. 사람이 확인한 실제 자세/이벤트와 계획 목표를 분리합니다.
4. 일부 프레임은 관절 정답을 표시해 좌표 정확도와 단순 출력률을 구분합니다.
5. 학습이 필요한 경우 참가자·세션 기준으로 분리하고 겹치는 영상/시간 창이 시험 자료에 섞이지 않게 합니다.
6. 이불·야간·엎드림 등 추가 조건은 현재 확정 범위와 분리한 확장 시험으로 표시합니다.

### 7.2 두 가지 비교를 구분

- **공통 조건 비교:** 공통 관절·같은 분류기·같은 분할로 관절 추정기 차이를 비교합니다. 전처리·임계값 선택은 검증 자료에서 수행합니다.
- **후보별 최적 구성 비교:** 모델 고유 관절·적절한 설정을 활용해 실제 운영 가능한 전체 구성의 성능을 비교합니다. 튜닝 비용·설정을 함께 보고합니다.

MediaPipe 33점과 COCO 17점은 수와 정의가 다릅니다. 이름만 보고 모두 1:1 대응시키지 않고 매핑표를 검수합니다. 고정/정답 사람 영역을 준 조건과 실제 검출기부터 실행한 조건도 분리합니다.

### 7.3 기록할 지표

| 판단 대상 | 지표/기록 | 선정에 주는 의미 |
|---|---|---|
| 관절 출력 안정성 | 관절별 누락·연속 실패·정지 구간 떨림 | 측정에 쓸 수 있는 유효 구간 확인 |
| 관절 위치 정확도 | 관절 정답 대비 PCK 등, 임계값·정규화 명시 | 잘못된 좌표를 출력 성공으로 오인하지 않음 |
| 자세 분류 | 클래스별 F1·macro-F1·혼동행렬 | 누움·옆누움·걸터앉음의 혼동 확인 |
| 판정 불가 | 전체 구간 대비 비율·지속 시간 | 불확실한 구간을 제외해 성능이 과장되는지 확인 |
| 이탈/복귀 | 이벤트 precision/recall·오경보/시간·시점 오차 | 실제 프로젝트 목적과 연결 |
| 실시간 처리 | 전체 지연 p50/p95·처리량·프레임 드롭 | 추론만 빠르고 결과가 늦게 도착하는 문제 확인 |
| 장비/운영 | 메모리·CPU/GPU·설치 재현성·장시간 동작 | 실제 Windows 환경에서 운용 가능 여부 |
| 외부 센서 비교 | 공통 유효 구간 일치율·불일치·시점 차이 | 독립 시스템 비교. 모델의 정답 정확도와 별도 |

수치 목표·허용 지연·평가 시간창은 미정입니다. PC 성능, 외부 센서 주기와 최종 라벨을 확인한 뒤 설정합니다.

### 7.4 선택 규칙 제안

- 필수 자세에서 관절이 반복적으로 실패하면 단순 FPS 이점만으로 채택하지 않습니다.
- 모든 모델이 같은 시점에서 실패하면 카메라 위치·화각·노출·신체 크롭부터 점검합니다.
- 관절은 맞지만 자세가 틀리면 분류 특징·라벨 정의·시간 분석을 우선 점검합니다.
- 관절 추정이 특정 자세에서 계속 틀리고 라벨 확보가 가능하면 YOLO Pose·RTMPose·HRNet 추가 학습을 검토합니다.
- 추가 장비는 실패 원인이 가림/깊이/조명 중 무엇인지 확인하고 해당 원인을 보완할 때 검토합니다.
- 최종 선택에는 모델·가중치·버전, 실행 환경, 정확도/지연 근거, 사용한 코드·가중치·데이터 이용 조건을 기록합니다.

## 8. 근거를 읽을 때 피해야 할 해석

| 확인된 내용 | 확대 해석하면 안 되는 내용 |
|---|---|
| MediaPipe의 일반 자세 평가 | 침대에서 가장 정확함 |
| YOLO Pose의 사용자 데이터 학습 지원 | 추가 학습하면 반드시 개선됨 |
| RTMPose의 공개 벤치마크 속도 | 우리 PC 전체 처리 속도 |
| HRNet 기반 침대 센서 융합 결과 | RGB 사전학습 HRNet 또는 다른 모델도 같은 성능 |
| 열화상 연구의 안정된 누운 자세 | 빠른 뒤척임·엎드림·모든 이불 조건 보장 |
| 3D 좌표 출력 | 실측 관절·침대 절대 위치 |
| 카메라와 외부 센서의 일치 | 두 시스템의 정답 |
| PCK/AP 향상 | 자세 분류·이탈 탐지 성능이 같은 폭으로 향상 |

SLP는 RGB·LWIR·깊이·압력맵을 포함하는 침대 자료의 학습/평가 후보입니다. 모델 자체가 아니고, 기존 SLP 누운 자세 자료를 이탈·복귀 연속 이벤트 정답으로 가정하지 않습니다. [S14]
