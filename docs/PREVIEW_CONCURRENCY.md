## 실행과 자원 경계

기존 입력별 LiveWorker가 수신·추론·판정·기록을 소유한다. WebWorkspace 모니터는 메시지와 최신 처리 결과를 수집하고 기록 수/경과·처리 FPS를 갱신한 뒤 입력별 PreviewWorker에 표시 작업을 제출한다. 인코더는 공통 작업실 잠금을 잡지 않고 JPEG를 만든다. 각 입력은 변환 중인 한 작업과 교체 가능한 최신 대기 작업 하나만 유지한다. 화면용으로 건너뛴 결과를 원본 기록에서 누락시키지 않는다.

뷰는 변환에 사용한 프레임의 시각·관절·대상·자세·실루엣과 함께 한 묶음으로 공개한다. 변환이 느리면 해당 입력의 화면 관측은 늦을 수 있으며 이를 새로운 관측으로 바꾸거나 이전 마스크를 새 영상에 결합하지 않는다. 화면용 세대가 역행하는 결과는 버린다. 기록 수와 처리 FPS는 표시 변환과 별도로 갱신하고, 자세/대상 화면은 공개된 영상 관측과 대응한다. 두 시점 결합의 기존 시간/대상 게이트와 기준은 유지한다.

## 화질 전환·실패·종료

화질 명령끼리는 전용 잠금으로 직렬화한다. 현재 프레임 스냅샷을 얻고 공통 잠금 밖에서 모두 변환한 후 설정을 적용한다. 준비 실패 시 기존 설정을 유지한다. 움직이는 입력이 준비 중 전진한 경우 이전 세대의 뷰를 덮어쓰지 않고 최신 프레임을 새 화질로 다시 제출한다. 정지 입력은 같은 프레임을 전환한다. 이전 화질의 비동기 결과는 화질 버전으로 거부한다.

JPEG 실패는 기존 preview_error로 분리하며 측정/추론을 종료하지 않는다. 입력 자체 오류는 표시 캐시·대기 작업을 폐기하고 입력 유효 버전을 바꿔 진행 중 결과도 거부한다. 삭제된 입력의 결과는 재등록하지 않는다. 종료 시 대기 작업을 비우고 표시 스레드를 종료 요청한다. 이미 실행 중인 네이티브 인코딩은 강제 중단할 수 없어 제한 시간만 기다리는 daemon 스레드를 사용하며 늦은 결과를 반영하지 않는다.

RAM에는 현재 입력 캐시 외에 변환 중 프레임과 화질 전환 스냅샷이 일시 유지될 수 있다. 입력 수/해상도에 따른 메모리와 CPU·전송 부담은 남는다. 이 변경이 물리 카메라 FPS나 촬영 동기화를 보장하지 않는다.

## 검증

`test_preview_concurrency.py`는 한 인코더를 Event로 멈춘 동안 다른 입력 갱신·상태 조회·기록 진행·입력 제거가 가능한지 검사한다. 대기 작업의 최신 값 교체와 화질 명령 중 관측 전진·설정 반영·프레임 대응도 확인한다. 기존 화질·오류 복구·실루엣·카메라 설정 브라우저 회귀 검사를 함께 사용한다. 실제 다중 카메라 처리율·종단 지연·장시간 자원 측정은 별도 검증이다.
