입력 추가에서 카메라마다 해상도(장치 기본·640×480·1280×720·1920×1080)와 FPS(기본·15·30·60)를 요청합니다. 연결 후 요청값·실제 RGB 프레임 크기·장치 보고 FPS·최근 처리 FPS를 분리해 표시합니다. 요청·속성 설정 반환값·드라이버 보고값은 source_profile에 남기며 실제 영상 크기는 기존 측정 geometry에 보존합니다. 지원하지 않는 속성은 실제 수신값으로 확인하며 연결 후 설정 변경은 재연결로 수행합니다. 실제 장치 협상·해상도별 속도/정확도 검증은 남아 있습니다. ## 브라우저 표시 화질 · 2026-10-28

상단 **화질**에서 기본 **고화질 · 1920px** 또는 **표준 · 1280px**를 선택합니다. 긴 변 기준이며 16:9 가로 영상의 최대치는 고화질 1920×1080/JPEG 95, 표준 1280×720/JPEG 85입니다. 카메라가 더 낮은 해상도로 보내면 확대하지 않습니다. 영상 아래 **입력 W×H → 전달 W×H · JPEG Q**에서 실제 값을 확인합니다. JPEG 수치는 인코더 설정이고 ‘원본 화질의 Q%’가 아닙니다. [같은 프레임 전환·여러 화면·한계](PREVIEW_QUALITY.md).

## 기록 시간축 검토 · 2026-10-28

**측정 기록 보기**에서 완료 기록을 선택하면 시간축 요약이 나타납니다. 저장 자세의 구간별 프레임 분포·점수 평균/최소/최대·보류 사유·실루엣 충돌을 확인하고 그래프 클릭 또는 슬라이더/이동 버튼으로 해당 원본 프레임을 강조합니다. 조회 중 실시간 측정은 계속됩니다. 저장 영상은 원본 PTS를 기본 시간축으로 사용하고 수신 경과로 바꿀 수 있습니다. 현재 화면은 영상 재생이 아니며 원본 판정/기록을 바꾸지 않습니다. [사용법과 해석 주의](RECORD_TIMELINE.md).

## 영상 위 실루엣 표시 · 2026-10-28

상단 **실루엣 표시**를 켜면 선택 대상의 추정 인물 영역을 반투명 보라색으로 확인합니다. **관절 표시**와 별도로 켜고 끄며 여러 화면 보기에도 적용합니다. 기본은 둘 다 켜짐입니다. 관절이 부족해 자세 판정이 보류돼도 마스크/대상이 유효하면 표시합니다. 여러 사람이 있는데 대상을 고르지 않았거나 추적 보류·분할 미지원이면 표시하지 않고, 개별 영상 아래에 ‘실루엣 없음’을 안내합니다. 영상과 실루엣은 같은 프레임으로 전달하며 원본 비율을 유지합니다. 전체 마스크 미리보기는 기록하지 않고 기존 지점별 희소 표본/보조 결과만 저장합니다. [표시·성능 한계](SILHOUETTE_SUPPORT.md#영상-위-실루엣-표시--2026-10-28).

## 영상 보조 근거 · 2026-10-28

HTML 작업실은 동일 MediaPipe 모델의 분할 출력을 활성화합니다. 오른쪽 **영상 보조 근거**에 몸통 7지점 주변과 인물 영역의 일치·충돌·확인 불가를 표시하고 ‘검사 지점’에서 세부 출력값을 봅니다. 보조 상태는 최종 자세·점수에 반영하지 않습니다. 같은 모델의 추정이며 분할/관절 정확도 검증은 아닙니다. 희소 표본과 보조 상태를 측정 파일에 저장하고 기록 조회 및 CSV에도 표시하며, 마스크가 없거나 대응이 불확실하면 확인 불가로 남깁니다. [설정·자료형·기록 및 한계](SILHOUETTE_SUPPORT.md).

## 측정 기록 보기 · 2026-10-28

## 실행과 화면 구성

PC의 넓은 창에서는 영상·측정 조작을 왼쪽에, 자세 판정과 관측 상태를 일정 너비의 오른쪽 한 열에 표시합니다. 영상 틀 높이는 브라우저의 가용 높이에 맞춰 제한하며 원본 전체를 비율 유지해 표시합니다. 영상과 틀의 비율이 다르면 여백이 남지만 가장자리를 자르거나 관절 좌표를 늘이지 않습니다. 작은 창에서는 상태 카드를 영상 아래에 배치하며 ‘여러 화면 보기’의 격자 열 수도 가용 너비에 맞춰 바뀝니다. 오른쪽 설정이 길면 해당 열에서 스크롤할 수 있습니다. 입력 전에는 연결 안내·측정 순서를 보여 주고, 입력 후에는 측정 조작·관측 상태를 표시합니다. 두 카메라 그룹 측정 설정은 오른쪽 접이식 패널에 있습니다.

프로젝트 폴더 PowerShell에서 아래 전체를 실행합니다. Python 3.12 가상환경과 기존 로컬 모델을 사용합니다.

```powershell
& .\.venv\Scripts\python.exe -m pip install -e ".[live]"
& .\.venv\Scripts\python.exe -m bed_pose live
```

실행하면 **기본 브라우저에 HTML 측정 화면**이 열립니다. 기존 Tk 창은 기본 실행에서 사용하지 않습니다. 자동으로 열리지 않으면 터미널의 `http://127.0.0.1:.../#...` 주소 전체를 복사하세요. Python 터미널은 실행 상태로 유지해야 합니다. 저장 결과용 `render/index.html`과 달리 실시간 분석은 같은 PC의 Python 서버가 필요하며 HTML 파일을 더블클릭하는 독립 실행은 아닙니다.

‘입력 추가’에서 카메라 또는 영상 파일을 선택합니다. 기본 모델은 `checkpoints/pose_landmarker_full.task`이며 대화상자의 ‘모델 변경’으로 `.task` 파일을 선택할 수 있습니다. 선택한 모델은 이후 새 입력에만 적용됩니다. 기본 실행은 장치를 자동으로 열지 않습니다.

- **왼쪽:** 입력 목록과 ‘입력 추가’. 클릭해 입력별 영상을 전환합니다.
- **입력 추가 대화상자:** 카메라 번호/장치 확인, 촬영 파일 선택, 모델 변경.
- **중앙:** 큰 영상과 관절 표시 전환, ‘침대 영역 지정’ 네 점 클릭 조작.
- **오른쪽:** AI 자세 판정, 관절 검출 후보, 침대 영역 상태. 이탈·복귀 상태도 별도로 표시합니다.
- **하단:** 영역 지정 안내, 측정 시작/종료, 파일 재생/일시정지, 기록 상태·프레임 수·결과 경로.

현재 자세 분류기가 없으므로 **‘판정 기능 준비 중’**을 표시합니다. 바로 누움·옆으로 누움·걸터앉음은 예정 분류이고 현재 예측이 아닙니다. 후보 있음/없음은 관절 검출 결과이며 자세명·정확도·침대 점유 판정으로 대체하지 않습니다. 입력/추론 오류에는 이전 결과를 현재 관측처럼 유지하지 않습니다.

## 카메라 선택과 휴대폰

현재는 OS 장치 이름으로 선택하고 ‘카메라 연결’을 누릅니다. Windows에서는 같은 장치의 중복을 줄이기 위해 DirectShow 목록을 사용합니다. 실제 장치 매핑은 PC에서 확인해야 합니다. 다음 번호 탐색 설명은 이름 열거가 불가능한 경우의 대체 경로입니다. ‘장치 확인’은 사용 중인 장치를 제외하고 **0~5번을 열고 프레임 수신을 확인한 뒤 해제**합니다. UI와 별도 스레드로 실행하며 장치별 응답 시간이 길 수 있습니다. 이것은 OpenCV의 제한된 번호 탐색이지 모든 장치·고유 이름을 열거하는 기능이 아닙니다. 다른 번호는 직접 입력할 수 있고 운영체제/연결 순서에 따라 번호가 바뀔 수 있습니다. 확인 과정에서 장치 표시등이 켜질 수 있습니다.

내장 카메라, USB 카메라와 **PC에서 웹캠으로 인식되는 휴대폰**을 같은 방식으로 선택합니다. 휴대폰을 USB로 연결하는 것만으로 카메라가 되는 것은 아닙니다. OS/드라이버의 웹캠 기능 설정이 필요할 수 있으며 휴대폰 앱·드라이버 설치/네트워크 스트리밍 URL 입력은 이 앱의 기능이 아닙니다.

다른 번호의 카메라를 추가하면 왼쪽 입력 목록에 추가됩니다. 같은 카메라를 중복해서 열지는 않습니다. 연결 실패 시 합성 입력으로 바꾸지 않습니다. OpenCV 기본 backend와 실제 backend·버전·드라이버 FPS를 기록합니다. 장치 응답이 멈추면 종료도 지연될 수 있으며 자동 재연결은 없습니다.

## 기존 촬영 영상 활용

‘입력 추가 → 영상 파일’에서 MP4/MOV/MKV/AVI/WebM 등을 선택합니다. 브라우저 파일 선택으로 같은 PC의 OS 임시 폴더에 분석용 복사본을 만듭니다. 영상은 최대 16GB, 모델은 512MB를 허용하며 전달 진행률을 표시합니다. 업로드라는 HTTP 동작은 이 PC의 loopback 서버로만 전송하는 과정이며 외부 서비스에 전송하지 않습니다. 임시 복사본은 정상 작업실 종료 시 삭제되며 강제 종료 시 OS 임시 폴더에 남을 수 있습니다. 실제 지원 여부는 PyAV/FFmpeg의 디코더·영상 형식에 따릅니다. 첫 비디오 스트림을 분석하며 오디오는 재생하지 않습니다. 기존 디코더의 회전·픽셀 종횡비 정책을 재사용합니다.

1. 첫 프레임에서 자동으로 일시정지합니다. 침대 모서리 네 점을 클릭할 수 있습니다.
2. ‘측정 시작’은 **다음 프레임부터** 기록하면서 재생합니다. 첫 미리보기 프레임은 기록 구간에 포함하지 않습니다.
3. 재생/일시정지는 분석 진행만 제어하며 측정 중 조작 시각·적용 프레임을 기록합니다. 측정하지 않고 미리보기 재생도 가능합니다.
4. ‘측정 종료’는 기록을 마치고 파일 진행을 일시정지합니다. 남은 구간에서 새 측정을 시작할 수 있습니다.
5. 영상 끝은 정상 종료이며 진행 중인 기록을 정리합니다. 디코딩 오류와 구분하고 마지막 결과임을 표시합니다. 처음부터 다시 분석하려면 파일을 새로 엽니다.

프레임을 건너뛰지 않고 **처리 가능한 속도**로 재생합니다. 원본 재생 속도를 보장하거나 파일 처리 시간을 실제 동작 시간으로 해석하지 않습니다. SDK 시간은 원본 PTS에서 최초 프레임 시각을 뺀 ms이며 원본 정수 PTS/time base·상대 ns·프레임 ID·RGB 픽셀 해시를 보존합니다. PTS가 없거나 증가하지 않는 경우 실패로 종료합니다. ms 내림 후 시각이 중복되어도 임의로 +1ms 보정하지 않습니다. 탐색/되감기·배속·중간 프레임 수정은 아직 없습니다.

동일 파일의 모델 비교·정식 진단에는 기존 `prepare/run/evaluate/compare/render` 경로를 사용합니다. 이 화면에서 선택한 구간 기록은 benchmark의 전체 프레임·초기화 조건과 다릅니다.

## 여러 입력의 의미

각 입력은 별도의 **소스·SDK 인스턴스·시계·침대 영역·측정 폴더**를 가집니다. 목록에서 선택하지 않은 입력도 연결/분석과 진행 중인 측정 기록을 계속합니다. 왼쪽 각 입력의 휴지통 버튼은 선택하지 않은 입력도 직접 제거합니다. 선택한 입력은 영상 아래 ‘입력 닫기’로도 제거할 수 있습니다. 해당 소스와 진행 중인 기록을 정리한 뒤 목록에서 제거하며, 원본 파일과 이미 저장한 측정 결과는 삭제하지 않습니다. 정리 중인 입력의 제거 버튼은 비활성화합니다. 마지막 입력을 제거하면 입력 추가 화면으로 돌아갑니다. 브라우저 새로고침은 서버 상태를 복원합니다. **브라우저 탭만 닫아도 측정은 계속됩니다.** ‘작업실 종료’ 또는 터미널 Ctrl+C로 모든 입력과 기록을 정리합니다. 장치가 응답하지 않으면 종료가 지연될 수 있습니다.

이는 여러 카메라를 독립적으로 여는 기능입니다. **그룹 시작/종료·원본 기록 연결·수신 시각 근사 정렬과 운영자 동일인 지정은 구현**했습니다. 실제 노출 동기화·카메라 보정·검증된 인물 연결·3D 융합·통합 자세 분류는 미구현입니다. 여러 SDK 실행 시 CPU/메모리·USB 대역폭 부담이 늘 수 있고 실제 장치 수·처리율 한계는 미측정입니다. 최초 MediaPipe 설정은 기존 CPU/연속 모드와 최대 후보 1개를 재사용합니다. 카메라 수와 한 화면의 사람 수는 다른 개념이며 수동 대상 선택과 관절 이동 기반 잠정 추적·보류/재지정을 지원하며 실제 동일인 신뢰성은 미검증입니다.

## 침대 영역과 측정

‘침대 영역 지정’을 누르고 침대 모서리 네 곳을 순서대로 클릭합니다. Escape는 지정을 취소합니다. ‘점 위치 수정’으로 모서리를 이동할 수 있습니다. 직접 지정한 영상 영역이며 자동 인식·실제 경계 정답·실측 좌표가 아닙니다. 첫 영상과 영역이 준비돼야 ‘측정 시작’이 활성화됩니다.

- 개별 측정과 그룹 준비/기록 중 점을 다시 지정/이동하거나 영역을 지우면 새 버전·요청 시각·적용 시각·적용될 첫 프레임을 기록합니다. 지운 뒤에도 기존 측정은 계속되지만 다음 측정 시작에는 영역을 다시 지정해야 합니다.
- 카메라는 한 연결 동안 고정해야 합니다. 영상 크기 변경은 실패로 종료하고 이전 영역을 재사용하지 않습니다. 같은 크기의 카메라 이동은 감지하지 못합니다.
- 측정 종료는 flush/fsync·파일 해시·기록 검사 후 표시합니다. 다시 시작하면 새 폴더이며 매우 짧은 측정은 기록 프레임이 0개일 수 있습니다.
- 카메라 원본 영상/이미지는 녹화하지 않습니다. 선택한 촬영 파일의 분석용 임시 복사본은 녹화 결과와 별개입니다. 선택적 녹화는 후속입니다. 기록 실패는 정상 완료로 표시하지 않습니다.

## 기록과 시간 의미

기본 위치는 `recordings/live/<measurement_id>/`이며 `--output-root`로 바꿉니다. `manifest.json`, `live_frames.jsonl`, `control_events.jsonl`을 생성합니다. 현재 **live-0.2-draft**이고 기존 카메라의 **live-0.1-draft 읽기 검증도 유지**합니다. 최종 센서 교환 형식은 아닙니다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live-inspect --run "recordings/live/<measurement_id>"
```

`live-inspect`는 해시·카운터·식별자·시간 순서·PTS/SDK 시간 관계·영역 버전·옵션/profile·미구현 출력 상태를 확인합니다. failed 실행도 ledger_complete=true일 수 있습니다. 이는 남긴 기록의 완결성이며 실제 관절 정확도·전체 노출 프레임 수신·영상의 정답을 검증하지 않습니다. 기존 `inspect/evaluate/render`는 이 형식을 받지 않습니다.

| 항목 | 의미 |
|---|---|
| measurement_id / frame_id | 측정 폴더와 그 안의 0부터 시작하는 기록 순서 |
| stream_id / stream_frame_id | 한 입력 연결과 미리보기를 포함한 프레임 순서 |
| read_started_ns / received_ns | 해당 입력의 perf_counter 기준 경과 ns. read가 RGB 반환까지 마친 시각이며 파일에서는 디코드/수신 시각 |
| camera_exposure_ns | null. 수신 시각을 노출 시각으로 대체하지 않음 |
| received_utc_ns | 시스템 UTC 표본이며 센서/다른 카메라와 동기화됐다고 가정하지 않음 |
| model_timestamp_ms | 카메라: received_ns/1e6 내림. 파일: 원본 최초 PTS 대비 경과 ms 내림 |
| source_media | 파일만 원본 source_frame_id·PTS·time base·상대 ns·픽셀 해시 보존 |
| inference_started/finished_ns / mapping_finished_ns | 입력별 단조시계의 실제 처리 경계 |
| record_started_ns | JSON 직렬화/쓰기 시작 전 시각. 쓰기 완료 시각이 아님 |
| control_events / request | 제어 적용과 버튼 요청 시각. 파일 수동 재생/일시정지도 별도 이벤트 |
| initial_bed_selection / selection / bed_region_revision | 영역을 지정한 미리보기 프레임·요청/적용 시각·영역 변경 이력 |
| raw_candidates / mapped_people | 원본 관절/점수와 공통 17점. 수치 유효성과 실제 정확도는 다름 |
| target_posture / verified_gt / sensor_results | 각각 null. 목표·정답·외부 결과를 카메라 예측으로 대체하지 않음 |
| posture_prediction / event_analysis_status / bed_occupancy_status | not_implemented. 빈 이벤트 목록도 ‘이벤트 없음’ 판정이 아님 |

원본 파일은 경로·SHA-256·디코더 프로필을 기록하고 열기/닫기 시 해시를 확인합니다. 파일을 분석 도중 수정하지 마세요. 코드/환경·모델 자산 해시·어댑터 옵션·매핑도 기록합니다. SDK 초기화 옵션 파일은 임시 경로일 수 있고 실제 옵션 값은 profile에 남습니다. 앱 안에서 불러오는 원본도 GitHub 업로드 대상이 아닙니다.

입력별 한 작업 스레드가 수신/추론/기록을 소유합니다. `live_factory.py`는 GUI와 독립적인 엔진 생성, `live_web.py`는 상태/제어 API와 화면 전달, `templates/live_workspace.html`은 브라우저 화면/조작을 담당합니다. 표준 HTTP 서버를 재사용하며 새 웹 프레임워크 의존성은 없습니다. 처리 결과는 **기록 후** 화면용 크기 1 큐로 보냅니다. UI가 느려 교체한 결과 수는 카메라 하드웨어 프레임 손실 수가 아닙니다. 드라이버 손실·버퍼 지연은 미확인/null입니다. 미리보기 SDK 이력은 측정 시작에도 유지하며 manifest의 tracking_scope=input_stream, preview_tracking_history_retained=true로 표시합니다.

전원 장애/강제 종료 복구 모드는 없고 최종 파일 fsync와 미완료 표시만 제공합니다. 디렉터리 fsync나 절대적 내구성을 보장하지 않습니다.

## 로컬 실행 경계

서버는 `127.0.0.1`의 자동 할당 포트에서만 실행합니다. API는 실행별 토큰/Host/Origin을 확인하고 화면은 외부 CDN·폰트·분석 서비스에 요청하지 않습니다. 원본/모델 업로드는 임의 파일명 대신 임시 UUID 경로에 저장합니다. 브라우저 카메라 API가 아니라 Python OpenCV가 같은 PC의 장치를 엽니다. 휴대폰 원격 제어나 외부 공개 서비스로 배포하는 기능은 아닙니다.

JPEG 미리보기는 긴 변 1280px 이하로 줄여 전달할 수 있습니다. 원본 RGB 관절 추론과 기록 좌표는 유지하며 한 응답에 JPEG·동일 프레임의 관절/ID를 묶습니다. 미리보기 해상도와 원본 분석 해상도를 구분합니다.

## 검증 범위

개발 검사 92개를 통과했습니다. 기존 85개에 로컬 API 접근 제한·파일 업로드·JPEG/프레임 ID·영역/측정/기록 검사·파일 EOF·입력 분리/제거·오류 화면 제거·종료 정리 검사를 추가했습니다. Chromium에서 실제 HTTP 서버를 열어 입력 대화상자·합성 영상·영역 드래그·측정·관절 표시·브라우저 파일 선택/재생/일시정지/EOF·새로고침·입력 제거·종료와 좁은 화면의 가로 넘침을 확인했습니다. 카메라 선택/조회·중복 거부·오류 표시는 모의 장치로 확인했습니다. 0.8.0 wheel의 저장소 밖 설치본에서도 브라우저 조작과 실제 launcher의 HTTP 시작/종료를 확인했습니다. 실제 생성 영상 디코더와 테스트 SDK를 사용하며 AI 성능 검증은 아닙니다.

**실제 다중 카메라·휴대폰 웹캠·Windows 장치 권한/기본 브라우저 연동·장치별 지연은 아직 검증하지 못했습니다.** 사용자 PC 확인과 실제 침대 영상의 정답 기반 관절/자세 성능 검증이 남아 있습니다.


## 여러 화면 동시 표시

상단 ‘여러 화면 보기’는 연결된 모든 입력을 격자로 동시에 표시합니다. 각 영상에 관절/침대 영역과 입력별 측정 상태를 표시하며, 영상을 클릭하면 개별 화면으로 이동해 영역 지정/측정 조작을 할 수 있습니다. 측정 버튼은 ‘선택한 입력’에만 적용되고 다른 입력의 진행 중 측정은 유지됩니다. ‘개별 화면 보기’로도 전환할 수 있습니다. 여러 영상 응답을 병렬로 가져오지만 카메라 간 동기화·결과 융합은 수행하지 않습니다. 동시 입력 수가 늘면 CPU/전송 부담도 증가합니다.


## 두 카메라 그룹 측정 · 기록 연결 구현

상단 ‘두 카메라 그룹 측정’을 펼칩니다. 각 입력의 개별 화면에서 침대 영역을 지정한 뒤 서로 다른 입력 두 개를 고릅니다. 아래 대상 지정 절차로 양쪽 사람을 선택하고 운영자 동일인 확인·허용 시간 차이를 설정한 뒤 ‘그룹 측정 시작’을 누릅니다. 카메라끼리 또는 파일끼리 묶을 수 있고, 다른 측정에 참여 중인 입력은 선택할 수 없습니다. 그룹 측정 중 개별 시작/종료·영역 변경·재생 조작은 막고 그룹 종료를 사용합니다. 격자 보기는 그대로 사용할 수 있습니다.

그룹 시작 요청을 두 Worker에 전달하고 실제 시작 ACK/원본 기록 폴더를 각각 연결합니다. 이는 같은 순간의 촬영을 보증하지 않습니다. 한쪽 시작 실패는 다른 입력도 정리하고 실패 그룹/부분 기록을 보존합니다. 입력 오류/EOF는 상대 입력도 종료하며, 그룹 입력 제거도 양쪽 기록을 정리한 후 처리합니다. 정상 그룹 종료는 양쪽 측정 기록을 마치고 미리보기 연결은 유지합니다. 원본 파일/기록은 삭제하지 않습니다.

`recordings/live/groups/<group_id>/manifest.json`은 `group-0.1-draft` 형식으로 양쪽 측정 폴더, 실제 ACK 시각, 원본 manifest SHA-256, 개별 기록 검사 결과와 시계 기준점/시작·끝 시각/프레임 수를 남깁니다. 원본 결과는 기존 측정 폴더에 있습니다. 부분 시작/검증 실패는 ledger_complete=false이며, 저장 실패 시 성공으로 표시하지 않습니다. 그룹 형식은 임시 내부 계약입니다.

**그룹 제어·기록 참조·종료 후 수신 시각 근사 정렬과 시점별 통합 입력 생성을 구현했습니다.** 운영자 대상 지정/잠정 추적을 사용하며, 검증된 동일인 식별·관절 좌표 융합·통합 자세 판정은 미구현입니다. 수신 시각과 실제 촬영 시각을 구분하는 [설계](MULTI_CAMERA_DESIGN.md)를 따릅니다.


## 그룹 프레임 시간 정렬 · 수신 시각 근사

그룹 설정에 ‘허용 수신 시각 차이(ms)’를 명시적으로 입력합니다. 검증된 기본값은 없으며 카메라 지연 실험에 따라 정할 설정값입니다. 입력값은 ns로 내림 변환해 group manifest의 alignment_max_skew_ns에 남깁니다. 두 입력의 같은 프로세스 perf_counter 기준점과 프레임 received_ns를 더해 공통 축을 구성합니다. UTC나 프레임 번호를 같은 촬영 순간의 근거로 쓰지 않습니다.

**성공한 그룹을 종료한 후** 양쪽 원본 기록을 검사하고 시간순 FIFO 일대일 정렬을 수행합니다. 앞 프레임끼리 시간 차이가 허용 범위 이하면 matched, 밖이면 오래된 프레임을 outside_tolerance 미매칭으로 남깁니다. 한쪽 기록 끝에 남은 프레임은 partner_end 미매칭입니다. 한 프레임은 한 번만 소비하며 최근접/최적 매칭이라고 주장하지 않습니다. 출력 후 양쪽 프레임 수와 참조 수가 같은지 확인합니다.

그룹 폴더의 alignment.jsonl은 양쪽 측정 ID·기록/스트림 프레임 ID·원래 시계/수신 시각·공통 축 시각·부호 있는 차이·미매칭 사유를 남깁니다. manifest에는 설정·방식·matched/양쪽 미매칭 수와 정렬 파일 SHA-256이 들어갑니다. ns는 문자열로 기록합니다. 정렬 중 메모리에 전체 영상을 올리지 않으며 추가 원본 프레임 재추론은 없습니다. 긴 기록은 종료 후 검사/정렬 대기 시간이 필요할 수 있습니다. 정렬 실패는 그룹 실패·미완료로 표시하고 원본은 유지합니다.

결과 상태는 receive_time_approximation이며 exposure_synchronized=false입니다. USB/휴대폰의 전송/버퍼/노출 지연 차이를 보정한 것이 아닙니다. matched는 같은 실제 촬영 순간이나 같은 사람을 보증하지 않습니다. 같은 사람 확인/관절 결합/통합 자세 판정은 여전히 미구현입니다.

저장 영상 그룹은 파일 상대 PTS의 공통 시작점/오프셋을 확인하지 못했으므로 blocked_media_offset_required로 표시하고 정렬 파일을 만들지 않습니다. 파일의 디코드 수신 시각으로 정렬을 대신하지 않습니다. 기존 설정 없는 API 호출은 이전처럼 기록 연결만 수행합니다.


## 양쪽 측정 대상 수동 지정

그룹 설정에서 입력 두 개를 고른 뒤 ‘첫 입력 대상 지정’, ‘두 번째 대상 지정’을 누릅니다. 각 창은 해당 입력의 한 프레임을 고정해 표시합니다. 관절 그림이나 후보 목록에서 선택하고 ‘이 후보 선택’을 누릅니다. ‘양쪽에서 같은 사람을 선택했습니다’를 직접 확인해야 새 HTML 화면의 그룹 시작이 활성화됩니다. 입력/대상 변경 시 확인을 다시 받아 잘못된 조합을 그대로 시작하지 않도록 합니다.

확인은 **운영자의 초기 동일인 지정**이며 AI 동일인 검증·자세 정답이 아닙니다. 그룹 manifest의 target_selections에 입력/스트림 ID, 선택한 프레임/시계/수신 시각·해상도·후보 ID와 공통 관절 스냅샷을 남깁니다. same_person_assertion은 operator_report_not_verified입니다. 선택용 JPEG는 RAM/브라우저에만 있으며 파일로 저장하지 않습니다. 입력별 최근 최대 4개 선택 스냅샷을 유지하고 입력 제거 시 정리합니다.

현재 SDK 후보 ID(p0 등)는 프레임의 순번이며 지속 인물 ID가 아닙니다. 최초 선택 이후 같은 ID가 나와도 같은 사람으로 자동 확정하지 않습니다. 현재는 아래 설명한 관절 이동 기반 잠정 추적을 사용하며 신원/동일인을 확정하지 않습니다. 미검출·입력 중단·복수 대응 후보·관절 정보 부족은 보류합니다. 기본 MediaPipe 설정은 최대 후보 1개여서 화면에 다른 사람이 있어도 모든 사람이 목록에 나온다는 보장은 없습니다. 실험용 잠정 추적을 구현했지만 자동 동일인 추적의 신뢰성은 별도 검증이 필요합니다.

대상을 지정한 그룹의 정렬 참조에도 target_association 상태를 남깁니다. 기존 추적 미설정 기록은 target_missing / target_ambiguous / observation_failed / continuity_unverified를 유지합니다. 새 추적 기록은 tracking_provisional 또는 held와 추적 구간 ID를 추가하며, 잠정 대응인 프레임에만 후보 ID를 남깁니다. identity_verified=false를 유지합니다. 따라서 관절 결합·자세 판정은 아직 보류/미연결입니다. 최초 프레임 지정 기능을 자동 추적 완료로 해석하지 않습니다. 저장 영상은 기존처럼 공통 시점 오프셋이 없으면 시간 정렬을 보류합니다.


## 관절 이동 기반 잠정 추적 · 실험용

대상 선택 창의 ‘이 후보 선택’은 Worker에 추적 초기화를 요청하고 실제 적용 응답을 기다립니다. 입력별 최근 256개 처리 결과 이력을 사용해 선택한 고정 프레임부터 현재까지 재생합니다. UI가 표시하지 않은 처리 프레임도 포함합니다. 선택 프레임이 만료되면 다시 지정해야 합니다. 이력에는 영상이 아닌 공통 관절/시간만 둡니다.

초기 방식은 pose_motion_unique_gate_v1입니다. 화면 내 수치 유효 관절의 공통 인덱스에서 이동 거리 중앙값을 계산하고, 영상 대각선과 경과 시간으로 정규화합니다. 설정 범위 안인 후보가 정확히 하나일 때 tracking_provisional로 연결합니다. p0/p1 순번이 바뀌어도 좌표 대응으로 따라갈 수 있지만, 위치가 비슷한 다른 사람으로 바뀌는 경우는 판별하지 못할 수 있습니다. 외형/생체 신원 인식·3D 추적·검증된 동일인 판정이 아닙니다.

대상 선택 창의 ‘추적 설정’에 실험용 초기값으로 최대 이동 속도 1 영상 대각선/초, 최대 관측 간격 500ms, 최소 공통 관절 4개를 제공합니다. 이는 검증된 정확도/품질 기준이 아니며 촬영 조건별 검증·조정이 필요합니다. 모델 점수 임계값을 추가하지 않습니다. 기본 모델 후보 수 1개는 실제 화면의 인원 수와 다르므로 다인 교차/교체 탐지를 보장하지 않습니다.

미검출, 관절/이동 범위 불충족, 여러 대응 후보, 관측 간격 초과, 시간 역행, 기하 변화, 처리 오류는 held로 전환합니다. 원본 관절 기록은 계속하지만 대상 대응 후보는 null로 보류합니다. 사람이 다시 보이더라도 자동으로 다시 붙이지 않습니다. 그룹 측정 중에도 각 입력의 대상 지정 버튼으로 재선택할 수 있으며, 새 추적 구간 ID를 부여합니다. 재지정 뒤 ‘양쪽에서 같은 사람을 선택했습니다’와 ‘두 대상 동일인 재확인’으로 운영자 확인을 다시 남깁니다. 확인 전은 reconfirmation_required이며 확인 후에도 신원 검증 완료가 아닙니다.

실시간 화면과 격자에 잠정 추적/보류 상태를 표시하고, 추적 후보는 녹색·다른 후보/보류 관절은 회색으로 구분합니다. 입력 종료는 추적도 보류합니다. 선택한 입력의 상태와 그룹 두 입력 상태를 구분합니다.

각 live_frames 행의 선택적 target_tracking에 구간 ID·프레임 후보·상태/사유·방법·실제 설정·identity_verified=false를 남깁니다. 초기 상태는 manifest의 target_tracking_initial, 측정 중 재선택은 control_events의 target_reselected에 기록합니다. 기존 target_resolution 필드는 호환을 위해 not_configured로 유지하며 이 실험 결과는 별도 필드에서 해석합니다. 정렬 참조에도 추적 결과를 보존하지만 카메라 사이의 신원/관절 융합이나 자세 결과를 생성하지 않습니다.


## 학습 전 통합 입력 생성 · 2026-10-28

그룹 종료 후 자동으로 원본 검사→근사 정렬→fusion_inputs.jsonl 생성을 백그라운드에서 진행합니다. 그룹 설정의 ‘통합 입력 준비 결과’를 펼쳐 입력 후보/보류 수와 사유를 확인할 수 있습니다. 입력 후보도 자세 판정·품질 검증 결과는 아닙니다. `group-inspect --run <그룹 폴더>`로 원본 참조·해시·파생 좌표/마스크·집계를 재검사할 수 있습니다. [형식·보류 조건·한계](TWO_VIEW_INPUTS.md)를 따르며 모델 학습과 자세 판정은 수행하지 않습니다.


## 단일 자세 계획 측정 · 2026-10-28

그룹의 ‘측정 방식’에서 단일 자세 계획 측정을 선택해 목표·준비 방식/시간·선택적 측정 시간을 설정할 수 있습니다. 준비 완료 또는 타이머로 시작하고, 설정 시간이나 그룹 종료로 마칩니다. 목표는 실제 정답/예측이 아닙니다. 준비 취소는 측정 프레임을 생성하지 않습니다. [사용 순서·시각/라벨 의미](SINGLE_POSTURE_PLAN.md)를 확인하세요. 순차 자세 측정은 후속입니다.
