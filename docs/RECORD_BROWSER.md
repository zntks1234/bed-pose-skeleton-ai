[진행 현황](PROJECT_STATUS.md) · [측정 작업실](LIVE_MEASUREMENT.md) · [적합도 판정](WEIGHTED_POSTURE.md)

## 사용법

기존 실행 명령은 같다.

```powershell
& .\.venv\Scripts\python.exe -m bed_pose live
```

1. 왼쪽 **측정 기록 보기**를 누른다. 카메라 연결 없이도 열 수 있다.
2. 목록에서 완료된 측정을 선택한다. 처음에는 목록 정보만 읽고, 선택할 때 원본 기록을 검사한다. 프레임 수에 따라 검사에 시간이 걸릴 수 있다.
3. 저장 당시 프레임별 자세·적합도·보류/참고 사유를 확인한다. 목록과 프레임은 기본 50개 단위로 이전/다음 페이지를 지원한다.
4. 닫기를 누르거나 Escape로 실시간 작업실로 돌아간다. **조회 중에도 기존 입력 분석·진행 중 측정은 계속된다.**

목록은 기본 `recordings/live/<measurement_id>/`에서 읽는다. `--output-root`로 실행했다면 그 위치를 사용한다. 같은 위치로 다시 실행하면 지난 측정도 조회할 수 있다. 현재는 작업실이 생성한 UUID 형식 폴더의 개별 입력 측정을 지원한다. 그룹 측정의 개별 입력 기록도 이 위치에 저장되면 조회할 수 있지만, 그룹 전체 통합 결과 화면과 오프라인 benchmark `runs/` 형식은 이번 범위에 포함하지 않았다.

## 표시 항목과 의미

| 항목 | 표시하는 내용 |
|---|---|
| 측정 목록 | 시작 시각(KST), 카메라/영상/합성 입력, 실행 완료/실패·미완료 상태, 기록 프레임 수와 ID |
| 기록 검사 | 열기 시 원본 해시·계약·당시 규칙의 결과 재계산 대조. 검사 전과 통과를 구분 |
| 실행 상태 | 기록 검사가 통과해도 실행 실패는 그대로 ‘실행 실패’로 표시 |
| 프레임 | 측정 안의 기록 순서와 입력 연결의 프레임 번호를 함께 표시 |
| 수신 경과 | `received_ns − manifest.started_ns`. 측정 시작 이후 처리·수신 시각이며 노출 시각이 아님 |
| 영상 상대시각 | 저장 영상의 원본 PTS 기반 상대 시각. 카메라/합성 입력에는 없는 값이며 `—` 표시 |
| 저장된 판정 | 당시 라벨, 보류, 판정 미사용, 처리 실패 또는 판정 필드 미기록을 구분 |
| 자세별 적합도 | 저장된 0.5의 독립 규칙 점수. 확률이 아니며 현재 가중치로 재분류하지 않음 |
| 결측 | 당시 적합도 계산 필드가 없으면 ‘계산 기록 없음’, 해당 프레임에서 비교 대상이 아니면 ‘조건 불충족’ |
| 보류·참고 | 당시 보류 사유, 가까운 점수 안내와 근거 충돌 경고, 처리 오류 코드 |
| 당시 설정 | 분류기 ID와 기록에 있는 최소 적합도 기준. 읽기 전용 |

‘기록 검사 통과’는 기록 내용의 일치 확인이며 **실제 자세의 정답·정확도 검증이 아니다.** 저장된 AI 판정을 실제 정답으로 바꾸거나 새 정답을 입력하는 기능은 추가하지 않았다. 프레임별 시각은 원본 ns를 유지하고 화면에서 초 단위 소수 셋째 자리로 표시한다.

## 보존과 실패 처리

- `RecordLibrary`는 파일·모델 설정을 읽기만 한다. 기존 판정 모듈·가중치·0.65 기준·최종 라벨 선택을 변경하지 않는다.
- 열기 시 `verify_live`가 당시 프로필로 순수 계산을 대조한다. SDK 추론·카메라/원본 영상 읽기는 하지 않으며, 저장된 판정이나 점수 필드를 채우거나 덮어쓰지 않는다. 당시 필드가 없는 이전 기록은 없는 상태로 보여준다.
- 기록 중/미완료 자료는 목록에서 구분하고 열기를 비활성화한다. 손상된 목록 항목 때문에 다른 정상 기록을 숨기지 않는다. 완료 표시는 검사 통과 전까지 무결성 보장이 아니다.
- 열어 둔 원본이 바뀌면 페이지 요청에서 해시를 확인해 읽기를 거부하고 이전 내용을 숨긴다. 원본이 변경된 채 새로 열면 검사 실패를 표시한다.
- 인증된 로컬 작업실 API만 사용한다. 임의 경로 대신 목록의 측정 ID를 전달하며, 저장 루트 밖 경로·심볼릭 링크를 따라가지 않는다. 텍스트는 HTML로 해석하지 않는다.
- 메모리는 열린 기록 최대 4개의 프레임 위치 색인만 보관하고, 원본 관절 전체를 누적 적재하지 않는다. 각 페이지에서 원본 변경을 확인하므로 큰 기록의 조회 속도는 디스크와 파일 크기에 영향을 받는다.

현재 원본 영상 녹화는 미구현이므로 이 화면에서 영상 재생은 제공하지 않는다. 결과 요약 그래프·시간별 자세 집계·화면에서 CSV 내보내기·기록 삭제/수정은 후속 작업이다. 기존 CLI CSV 내보내기는 그대로 사용할 수 있다.

## 검사 범위

전체 210개 개발 검사 통과. 합성 입력으로 실제 측정 파일을 만들어 원본 라벨/점수 일치·조회 전후 파일 해시 보존, 목록/프레임 페이지, 인증·경로 제한, 기록 중·손상·파일 변경·실행 실패, 0프레임 및 필드가 없던 이전 기록을 검사했다. Chromium에서 빈 목록, 완료/미완료 구분, 점수·근접 안내, 50프레임 페이지 이동, 조회 중 다른 측정의 진행, HTML 문자열의 안전한 표시, 390/1440/2560px 배치와 JavaScript 오류 없음을 확인했다. wheel의 현재 읽기 모듈·HTML과 문서 링크를 확인했다. 실제 Windows 장치·사람 영상의 인식 성능 검증을 뜻하지 않는다.
