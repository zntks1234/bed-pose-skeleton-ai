# 진행 현황

[프로젝트 홈](../README.md) · [문서 목차](README.md) · [다음 작업](../ROADMAP.md)

**기준일: 2026-10-31 · 실제 침대 영상 평가 준비 단계**

CLIP 사용 새 입력의 기본 조건은 사용자의 요청에 따라 `automatic-posture-rules-0.12`로, 유효한 영상 점수가 있으면 기준 미달이어도 가장 높은 신체 상태와 누운 방향을 선택합니다. 앉음은 침대 경계 근거를 참고하며, 서 있음과 기타도 그대로 표시합니다. 점수가 없거나 사람이 감지되지 않은 경우는 판정 불가입니다. 낮은 점수의 강제 선택은 오판 가능성이 높고 실제 정답 기반 정확도는 미검증입니다. GPU 관절 presence가 없으면 visibility를 확인하는 별도 크롭 정책을 사용합니다. [이전 0.11 분석](reviews/MANNEQUIN_POSTURE_CRITERIA_2026-10-31.md) · [두 측정 재검토](reviews/RECORD_REVIEW_2026-10-31.md).

0.11 이하 기존 경로와 과거 기록 검증은 유지하며 실제 일반 앉음·시점별 오분류는 미검증입니다. 이불 가림은 이번 기준의 검증 범위에서 제외했습니다. [이전 규칙](design/AUTOMATIC_POSTURE.md#골반무릎을-이용한-걸터앉음-보완--2026-10-31).

작업실의 관절 추정 모델 선택은 사용자 설정 폴더에 보관되어 재시작 후 복원됩니다. 모델을 변경해도 이미 열린 입력은 기존 모델을 유지합니다. [사용법](guides/LIVE_MEASUREMENT.md#설치와-실행).

이전 0.9 실험에서 사용자가 걸터앉음이라고 확인한 한 측정 기록 80프레임 중 73프레임이 걸터앉음으로 나왔지만, 이는 새 0.11의 정확도 검증이 아닙니다. 기존 기록의 재검사는 유지합니다.

그룹 측정 시작 버튼 아래에 현재 충족되지 않은 시작 조건을 표시합니다. 입력 상태·시간 차이·양쪽 침대 영역 확인 조건을 구분합니다. 사람이 없어도 측정 시작이 가능합니다.

라즈베리파이의 USB 카메라를 작업실 입력으로 추가했습니다. Pi의 MJPEG 스트림을 PC에서 수신하고 RTX 4060 MediaPipe 작업실에서 프레임을 처리했습니다. 네트워크 지연·실제 노출 시각·Pi 재부팅 후 자동 시작은 별도 검증이 필요합니다. [사용법](guides/LIVE_MEASUREMENT.md#라즈베리파이-usb-카메라).

작업실의 추론 실행 장치 패널은 선택한 입력의 MediaPipe·CLIP 장치와 준비·대기·중단 상태를 구분합니다. [사용 안내](guides/LIVE_MEASUREMENT.md#설치와-실행).

Windows의 선택형 MediaPipe GPU 실험 모드를 Python 작업실에 연결했습니다. 이 PC의 RTX 4060에서 실제 카메라 프레임 처리와 측정 기록 무결성을 확인했고, 별도 사람 이미지에서 33점의 변환과 기록을 확인했습니다. GPU 실루엣과 landmark presence는 미지원이며 실제 카메라의 사람 관절 기록·정확도·성능 비교는 추가 검증이 필요합니다. [실행 방법](guides/LIVE_MEASUREMENT.md#windows-mediapipe-gpu-실험-모드) · [독립 검증 화면](../tools/gpu-preview/README.md).

이 문서는 현재 지원 범위와 검증 상태만 관리합니다. 날짜별 변경 과정은 [개발 이력](archive/IMPLEMENTATION_HISTORY.md)과 [정리 전 기록](https://github.com/zntks1234/bed-pose-skeleton-ai/blob/98b1529bfea26f4679f9b19d3744d5c4f122d0da/docs/archive/PROJECT_STATUS_BEFORE_REORGANIZATION.md)을 참조하세요.

## 사람 영역 보완 — 2026-10-31

선택적 YOLOS-tiny 검출 경로를 연결했습니다. 관절 기반 영역이 부족할 때 현재 추적 대상의 몸통 관절과 대응하는 유일한 비중첩 영역만 사용합니다. 기본은 꺼져 있으며 `person-setup` 후 입력 추가에서 선택합니다. 영역 출처·검출 시간·품질/실패를 기록하고 재계산 검증합니다. 기존 CLIP 판정 기준과 과거 기록을 유지합니다. [사용·설계·제한](design/PERSON_CROP.md)

사람/몸통 자체가 미검출되면 복구하지 못합니다. 이전 영역 추적은 후속이며 시간적 안정화는 아래 별도 절을 참조합니다. 개발용 지정 출력과 작은 무작위 YOLOS 그래프의 연결을 확인했으며 사전학습 가중치 다운로드는 프록시 403으로 실패했습니다. 실제 영상에서의 개선과 추가 지연은 미검증입니다. Linux 개발 검사 339개·브라우저 4종·wheel 빌드를 통과했고 기존 관절 영역 정책 500개 비교 결과가 일치했습니다. 검출 대체 경로의 7개 검사에는 작은 무작위 YOLOS 그래프와 두 시점 기록 재검증이 포함됩니다.

## 순간·안정 자세 분리 — 2026-10-31

기존 순간 판정과 별도로 인과적 안정화 결과를 화면·개별/그룹 기록에 제공합니다. 초기값은 500ms·3개 관측 확인, 최대 관측 간격 1000ms·입력 만료 1500ms이며 입력 추가에서 조정합니다. 모두 미검증 초기값입니다. 보류·대상/분류기/영역 변경·간격 초과 시 근거를 초기화하고 입력 중단·종료 시 현재 라벨을 만료합니다. 원본 점수·라벨·정답 평가의 의미는 유지합니다. [설계·시간축·기록 계약](design/POSTURE_STABILITY.md)

단일은 분석 프레임, 라이브 그룹은 서버의 새 최신 관측 쌍, 저장 그룹은 FIFO 정렬 쌍으로 계산합니다. 라이브/저장의 샘플링 차이를 기록하며 동일 출력으로 주장하지 않습니다. 실제 자세 정확도·전환 지연 개선은 미검증이고 이탈/복귀 이벤트도 미구현입니다. Linux 개발 검사 349개·브라우저 6종·wheel 빌드를 통과했습니다. 안정화 전용 10개 검사는 시간/관측 수·중복·보류·시계/대상 변경·입력 만료·PTS·새 쌍·개별/그룹 재해시 변조 거부를 다룹니다.

- 이전 기능 커밋 [a5ee480](https://github.com/zntks1234/bed-pose-skeleton-ai/commit/a5ee4803eae61bb9cdc807c98e47ef60ced32266)의 [GitHub Actions](https://github.com/zntks1234/bed-pose-skeleton-ai/actions/runs/40798135896)는 Windows/Linux 테스트·빌드와 Linux 브라우저 검사를 통과했습니다.
- 2026-10-29 분리 구현은 Linux에서 전체 265개 개발 검사와 관련 후속 검사, 기존 브라우저 검사 2종·새 분리 브라우저 검사, 패키지 빌드를 확인했습니다. 생성 입력·SDK 대역 검사이며 실제 자세 정확도 검증은 아닙니다.
- 분리 커밋 c3128e3의 Actions는 Windows 통과·Linux 실패였습니다. 미리보기 치수 공개 전 FPS만 기다리던 테스트의 비동기 경쟁을 수정했습니다. 독립 영상 근거 연결·평가 도구의 최신 검사 결과는 해당 후속 커밋의 Actions를 기준으로 확인합니다.
- CLIP 라이브러리 설치/가져오기와 작은 무작위 가중치의 실제 Transformers CLIP 로딩·문장 캐시·이미지 추론을 확인했습니다. 연결·기록·브라우저는 명시적 대역으로 검사합니다. Hugging Face 다운로드는 프록시 403으로 차단돼 사전학습 가중치·첨부 마네킹·실제 사람의 CLIP 결과를 확인하지 못했습니다.
- 사용자 Windows PC의 실제 모델 실행과 일부 프레임 육안 검토 보고가 있습니다. 통제된 실제 장치 성능 시험과 구분합니다.
- 실제 사람의 관절 정확도·자세별 Precision/Recall/F1·보류율·전환 지연·다중 카메라 종단 지연은 아직 검증되지 않았습니다.
- 문헌 37편 중 P11·P12·P19·P34는 본문 미확인입니다. P35의 2022 ACM 최종판도 본문 미확인이고, 확인된 공개 판본의 근거만 사용합니다. [문헌 확인 범위](research/LITERATURE_REVIEW.md).

테스트 수는 변경되므로 이 문서에서 매번 누적하지 않습니다. 특정 실행의 결과는 해당 커밋의 Actions를 확인합니다. 기록 검사 통과를 자세 정확도나 실제 노출 프레임의 완전 수신으로 해석하지 않습니다.

## 카메라 단독 동작 보완 · 2026-10-30

CLIP 제공자 0.2는 신뢰도와 어깨·골반·하체 최소 관측을 검사하고 입력 영역/보류 사유를 기록합니다. 초기 품질 정책이며 전신 포함·정확도를 보장하지 않습니다. 이미지 제공자 오류는 관절 처리 성공과 분리해 표시/기록합니다. 추적은 측정한 직전 프레임 처리 시간을 관측 공백에서 구분하며, 미검출·다인 혼동은 계속 재지정을 요구합니다. 실루엣은 기본 비활성화했습니다. 실제 카메라 속도·인식 성능 검증은 남아 있습니다.

## 처리 자원·표시 개선 · 2026-10-30

CLIP 실행 장치는 기본 자동 선택(CUDA 지원 시 CUDA, 아니면 CPU)하며 CPU 연산 스레드의 기본 상한을 4로 제한합니다. 입력별 읽기·관절·이미지 처리 시간을 표시하고 실험 기록에 실제 CLIP 실행 설정을 남깁니다. 긴 상태 설명으로 형태 적합도 제목이 압축되던 열 배치를 수정했습니다. 실제 PC의 FPS 개선은 미검증이며 [속도 확인 방법](guides/LIVE_MEASUREMENT.md#처리-속도-확인과-실행-장치)을 따릅니다.

## 다음 단계

CLIP 사전학습 자산을 준비하고 마네킹/별도 검토한 사람 자료에서 실제 결과를 평가합니다. CLIP 실행 제공자는 구현했으며, 자산 준비·CLIP 선택 시 0.10이고 미사용 시 0.7입니다. 같은 자료의 SigLIP 2 비교와 최종 모델 선정은 후속입니다. 실제 영상에서는 한 명·한 카메라·이불 없는 세 자세 유지/전환과 서 있음 등 범위 밖 동작을 별도 주석으로 평가합니다. 이후 시점·가림·주변 인물·두 카메라로 넓힙니다. 순서와 완료 기준은 [로드맵](../ROADMAP.md)에서 관리합니다.

## 수신 분리·재검사 보완 · 2026-10-30

실제 카메라의 최신 프레임 수신 작업과 분석을 분리하고 개별 최신 영상/분석 프레임 전환을 구현했습니다. 저장 영상·여러 화면 격자는 순차 분석/분석 프레임 표시를 유지합니다. 분석하지 않은 수신 프레임 수를 기록하며 물리 장치 유실과 구분합니다. CLIP 입력 확인 PNG는 브라우저 근거 창 사용 여부에 따라 생성합니다. 제공된 Windows 309프레임 기록은 float 재계산 허용 오차 보완 후 Linux에서 무결성 재검사를 통과했습니다. 실제 카메라의 표시 FPS 개선·장시간·다중 장치 성능 검증은 남아 있습니다.

## 동시 수신 기록 종료 검증 수정 · 2026-10-30

수신 분리 후 기존 시간 검사에서 정상적인 프레임 간 수신/분석 겹침을 거부하던 오류를 수정했습니다. 겹침을 재현한 새 측정은 정상 종료·해시 재검사를 통과하고 시각 역행/분석 순서 오류는 계속 거부합니다. 사용자 379프레임 기록의 내용 검사는 통과했지만 원본의 실패/미완료 표시와 누락된 해시는 변경하지 않았습니다. 실제 장치에서 수정 후 새 측정의 종료 검증이 필요합니다.

## 인식 확인 화면 보완 · 2026-10-30

카메라 기본 화면을 관절·침대 영역이 표시되는 분석 프레임으로 변경했습니다. 표시 전환 버튼은 영상 상단에 배치하고 최신 영상만 모드에서는 관절 표시 조작을 비활성화해 실제 표시와 설정이 어긋나지 않게 했습니다. 수신/분석 분리 구조는 유지합니다.

## 최신 영상의 침대 영역 · 2026-10-30

최신 수신 영상에도 지정한 침대 경계와 모서리 번호를 표시합니다. 분석 프레임과 동일한 원본 좌표를 영상 비율·여백에 맞춰 변환하고, 영역 해제/입력 변경/크기 불일치 시 숨깁니다. 관절은 분석 프레임에서만 표시합니다.

## 표시·전송 경량화 · 2026-10-30

미사용 최신 영상 인코딩의 요청 기반 실행, 상태가 같은 응답의 304 처리·canvas 재그리기 생략, 고정 모델 설정의 브라우저 캐시를 구현했습니다. 전체 상태 API·기록 형식·모델 입력과 판정 계산은 유지합니다. 최신 영상 요청 중단/재개·화질 변경, 고정 설정 갱신/응답 분리, 변경 상태 전송을 모의 검사하며 실제 장치의 자원 절감 폭은 별도 확인합니다.

## 두 시점 통합 판정 · 2026-10-30

동일인·수신 시각 조건을 통과한 CLIP 그룹에서 사용 가능한 영상 상태/방향 점수를 결합합니다. 한 시점 제외 시 단일 시점 대체를 명시합니다. 개별 예측과 그룹 예측을 구분해 표시/기록하며 새 정책·출력 버전의 원본 기반 재검사를 지원합니다. 모의 점수·생성 입력 검증이며 실제 두 카메라 자세 정확도와 macOS 실기기 실행 검증은 남아 있습니다.

## Windows/macOS 실행 경로와 상주 모델 경량화 · 2026-10-30

CLIP에 MPS 장치 선택을 추가해 auto는 CUDA→MPS→CPU 순서로 확인합니다. 현재 Mac 설치 대상은 공식 패키지 배포가 있는 Apple Silicon·macOS 14 이상·ARM64 Python 3.12이며 Intel Mac은 별도 대응이 필요합니다. 고정 문장 특징 생성 후 문장 인코더를 해제해 이미지 판정 계산을 유지하면서 상주 가중치를 줄입니다. 실제 작은 무작위 모델에서 CPU 점수 동일성을 검사했고 macOS CI의 패키지·SDK 가져오기/모델 경계 검사를 추가했습니다. Mac 실기기 카메라·MPS 성공을 확인한 것으로 해석하지 않습니다.

## MediaPipe 전체 관절 표시 · 2026-10-30

MediaPipe 원본 33개 관절을 분석 화면·여러 화면·저장 영상 대조 화면에 표시합니다. 손가락·뒤꿈치·발끝과 얼굴 세부점을 포함합니다. 원본 33점 기록과 공통 COCO17 분석 좌표는 함께 유지하며, 기존 자세 판정·추적 기준과 기록 재검사 계산은 변경하지 않습니다. 최신 수신 화면에는 시각이 다른 관절을 겹치지 않습니다. 실제 카메라 표시 확인은 후속입니다.

처리 구간·GPU allocator 메모리·분석 화면 전달 진단, 선택적 CUDA 혼합 정밀도, 참조 수 기반 모델 공유와 선택적 준비 요청 묶음 추론을 연결했습니다. 기본 FP32·묶음 크기 1과 CPU/Mac 경로를 유지합니다. 동일 이미지 FP32/후보 비교 명령을 추가했으며 실제 GPU/Mac 실행·다중 카메라 지연·자세 정확도 유지 검증은 남아 있습니다. 새 추론 엔진은 비교 근거 확보 후 검토합니다. [사용법과 한계](guides/LIVE_MEASUREMENT.md#clip-최적화--2026-10-31).

## 보정된 두 카메라 3D 관절 근거

완료된 그룹 기록에서 동일 대상·수신 시각 게이트를 통과한 두 영상의 관절을 보정값으로 삼각측량해 기존 통합 자세 결과에 함께 내보냅니다. 보정값은 외부에서 준비하며 왜곡 제거된 핀홀 입력이 필요합니다. 선택적 깊이 판정은 기존 0.6 3D 기하 임계값을 재사용하고 영상 통합 결과와 일치할 때만 별도 결과를 냅니다. 기존 기록과 실시간 판정은 바꾸지 않습니다. Linux 가상환경에서 합성 기하·두 모의 카메라 그룹 기록부터 3D 근거 내보내기까지 확인했고 관련 검사 31개가 통과했습니다. 실제 카메라 보정·노출 오차·깊이 및 자세 정확도 검증은 남았습니다. [사용법](guides/STEREO_DEPTH.md)

실시간 두 카메라 영상 판정에서 기준 미달이어도 유효한 점수의 유일한 지원 자세가 있으면 해당 자세 이름을 표시하고 기준 미달을 안내합니다. 이는 확정 판정 및 저장 기록과 구분하며 시간·대상 불일치나 범위 밖 자세를 억지로 배정하지 않습니다. 지정 점수 및 브라우저 검사이며 실제 자세 정확도는 미검증입니다. [화면 사용법](guides/LIVE_MEASUREMENT.md#두-카메라-통합-자세)

## 카메라 영상 녹화와 로그 대응

단일 및 두 카메라 그룹 시작 시 선택적으로 분석 프레임을 FFV1/MKV로 저장합니다. 각 영상 프레임의 기록 프레임 번호·수신 시각을 인덱스에 남기며, 그룹의 정렬 기록을 통해 양쪽 영상과 로그를 연결합니다. 저장 기록에서 행을 선택해 대응 영상을 확인하고, 해시·프레임 수·타임스탬프를 검증합니다. 수신 완료 시각 기반이며 동시 노출은 아닙니다. 미분석 수신 프레임은 저장되지 않고 녹화 인코딩은 분석 워커에서 동기 실행됩니다. 합성 입력과 브라우저 검증만 완료했으며 실제 장치·장시간 속도와 저장 공간 검증은 남았습니다. [사용법](guides/LIVE_MEASUREMENT.md#카메라-영상-녹화와-로그-대조)

## 빈 침대에서 두 카메라 측정 시작

두 침대 영역을 확인하면 사람이 없어도 그룹 측정과 선택적 녹화를 시작합니다. 사람이 이후 나타나고 각 화면에서 침대 안 사람이 한 명씩 관측될 때 CLIP 통합 판정을 시도합니다. 단일 관측은 동일인 인증이 아니고, 미검출·침대 영역 내 다인·영역 관계 불명확 시 통합하지 않습니다. 빈 화면을 이탈이나 빈 침대의 확정 정답으로 취급하지 않습니다. 합성 입력과 브라우저 검증이며 실기기 정확도는 미검증입니다.

## 최신 main 기반 통합

0.12 영상 판정·순간/안정 자세·실행 장치 표시를 유지하면서 침대 영역 확인으로 빈 침대에서 두 입력 측정을 시작하고, 선택적 분석 프레임 녹화와 로그 대조를 연결했습니다. 보정 깊이 기록의 선택적 검사도 0.8~0.12 기하 설정을 지원합니다. 합성 입력 기준 전체 검사 415개 중 413개 통과·2개 건너뜀, 단일/두 입력 녹화와 자세·안정화 화면의 브라우저 검사를 확인했습니다. 실제 장치의 녹화 속도·동기화 오차·자동 대상 연결 및 자세 정확도는 미검증입니다.

## 침대 영역 사람 우선 선택

새 입력에서 최대 3명의 관절 후보를 요청하고, 신뢰도가 확인되는 양쪽 골반이 침대 영역 안에 들어온 사람이 한 명이면 주변 통행인보다 우선하여 단일·두 시점 자세를 계산합니다. 영역 안의 복수 후보·골반 불명확은 통합 보류하며, 침대 내 후보가 없을 때 단일 카메라의 기존 진단은 유지합니다. 동일인·물리적 점유 인증은 아닙니다. 이전 그룹 및 측정 기록은 기존 방식으로 재검증합니다. 합성 다인 및 기록 재생 검사를 수행했고 실제 환경에서 검출·가림·지연은 미검증입니다. [사용법](guides/LIVE_MEASUREMENT.md#침대-영역의-사람-우선-선택)

## 누움 출력 통합

화면과 기록 시간축에서 기존 `supine` 및 방향 미확인 `lying`을 `누움`으로 표시합니다. 새 안정화 버전 0.2에서는 두 값이 오가도 동일 자세로 처리하며, 이전 0.1 기록의 재검사는 기존 방식으로 유지합니다. 원본 자세 라벨·방향 점수·정답 평가 입력은 보존하므로 상세 데이터에서는 두 근거를 구분할 수 있습니다.
