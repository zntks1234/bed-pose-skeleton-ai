사용자 요청에 따라 기본 자동 규칙 0.4에서 몸통 기준 2D와 추정 3D를 최종 바로 누움·옆누움 판정에 연결했습니다. 2D가 애매한 프레임을 3D로 보조하고, 명확한 근거 충돌과 몸통 축 불일치는 보류합니다. 사용한 근거를 화면·원본 판정·CSV에 남깁니다. 0.1~0.3 로직과 기록 호환을 유지하며 추가 학습·관절 품질 보증·실제 정확도 개선을 주장하지 않습니다. 촬영 시점/몸통 방향이 누움 후보 조건 밖인 보류는 계속 남을 수 있습니다. [결정 흐름·초기값·후속 실측](LYING_ORIENTATION_RULES.md). 전체 193개 개발 검사와 Chromium의 3D 보조 최종 라벨·근거 충돌·3D 결측·2D 단독 경로·다중 보기·390/1440/2560px 표시를 확인했습니다.

## 모니터 기준 작업실 배치 재정리 · 2026-10-28

사용자 화면에서 영상이 지나치게 커지고 상태 카드가 가로로 흩어지는 문제를 확인해 배치를 다시 정리했습니다. PC 화면에서는 영상·측정 조작을 왼쪽에 두고 자세 판정·관측 상태를 300~340px 너비의 오른쪽 한 열에 모았습니다. 영상 영역 높이는 브라우저의 가용 높이에 맞춰 제한하며 원본 전체를 비율 유지해 표시합니다. 앞서 적용했던 원본 비율에 따른 영상 틀 확장 방식은 이 모니터 기준 배치로 대체합니다. 관절·네 점 영역은 기존 영상 좌표를 그대로 사용합니다.

입력 전에는 밝은 연결 안내와 측정 순서를 표시하고 비활성 측정 조작·관측 상태를 숨깁니다. 입력 후에는 영상·판정·측정 조작을 표시하며 그룹 설정은 오른쪽 접이식 패널로 옮겼습니다. 오른쪽 내용이 길면 해당 열을 스크롤하고, 작은 창에서는 패널을 영상 아래에 배치합니다. 영상 영역의 너비는 카드 내부의 100%로 유지합니다.

Linux Chromium에서 8개 창 크기 × 5개 상태(입력 없음·3개 영상 비율·복수 입력)의 가로 넘침·좌우 경계·영상 전체 표시를 확인했습니다. PC 크기에서 측정 조작과 오른쪽 열의 높이 제한, 입력 추가·그룹/자동 판정 설정 접근도 확인했습니다. 네 점 지정·이동·취소·교차 거부와 측정 기록 검사도 통과했습니다. 합성 입력으로 화면 동작을 확인한 것이며 실제 Windows 카메라 환경의 확인은 남아 있습니다.

## 공통 기반 구현 착수 · 2026-10-27 (이전 단계)

`src/bed_pose`에 프레임 식별 데이터형, 엄격한 JSON 설정 로딩·스키마 검사·상대경로 해석, 순차 프레임 ledger 프로토타입을 추가했습니다. 개발용 unittest 4개로 중복 JSON 키, 프레임 순서, 실패 실행의 기록 완결성, 미완료 상태 유지를 확인했습니다.

이 당시 ledger의 `frames.jsonl`은 기반 검사용 프로토타입 형식이었습니다. 이후 정식 FrameResult·원본/공통 참조와 영상·합성 어댑터를 연결한 범위는 아래 후속 기록을 따릅니다. 실제 SDK·평가·시각화는 미구현입니다. 설치된 개발 환경에서 `PYTHONPATH=src python -m unittest discover -s tests -v`로 검사했습니다. 모델 성능 검증이 아닙니다.

설정 로더의 가상 설정 파일에 대한 스키마 검사·설정 파일 기준 상대경로 해석도 별도 확인했습니다. 실제 입력 파일 존재·자산 해시 검증과 패키지 설치 검증은 아직 수행하지 않았습니다.

## 저장 영상·정식 기록·합성 어댑터 연결 · 2026-10-27

- `prepare`, `run`, `demo`, `inspect` CLI를 구현했습니다. 원본 PTS·time base·픽셀/파일 해시, 회전·색상 규약을 고정해 영상을 다시 읽고 확인합니다.

번호 입력 대신 OS 장치 이름 목록을 선택하도록 변경했습니다. cv2-enumerate-cameras의 backend 포함 인덱스를 OpenCV 입력에 그대로 사용하고 장치 이름을 입력 제목에 표시합니다. 같은 이름은 번호로 구분합니다. API 검사 7개는 통과했으며 실제 Windows 장치 이름/연결 매핑은 사용자 PC 검증이 필요합니다. 선택 의존성 재설치가 필요합니다.


## 카메라 선택 빈 목록 수정 · 2026-10-27

이름 목록이 없는 응답에서도 기존 indices를 선택 항목으로 표시하고, 빈 목록은 새로고침 안내를 유지합니다. 이름 열거 실패/빈 결과에는 번호 탐색으로 복구하며 기존 datalist 잔여 표시를 제거했습니다. API 검사 7개와 Chromium의 빈 상태·기존 0/1 응답·실제 이름 형식 응답을 확인했습니다. 구버전 서버를 종료한 뒤 재실행해야 합니다.


## 표시 지연과 카메라 중복 목록 수정 · 2026-10-27

브라우저의 고정 220ms 갱신 대기를 제거하고 처리 시간을 뺀 33ms 목표 주기로 변경했습니다. 서버 화면 전달 확인 주기도 15ms로 조정했습니다. 실제 처리 속도 보장이 아니며 카메라 수신/추론은 그대로입니다. 화면에 추론·수신 시간을 표시합니다. Windows 목록은 DirectShow 한 backend만 열거하고 backend를 포함한 선택 인덱스를 유지해 MSMF와의 중복 표시를 제거했습니다. API 검사 7개 및 모의 Windows 열거/인덱스를 확인했으며 실제 PC의 처리율·장치 지원은 확인이 필요합니다.


## 여러 화면 동시 보기 · 2026-10-27
