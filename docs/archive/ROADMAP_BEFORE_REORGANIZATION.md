## 저장 영상과 기록 프레임 대조 · 2026-10-29

완료 기록에서 원본 영상 파일을 선택하고 표의 프레임 번호 또는 시간축 이동으로 원본 프레임·저장 관절·침대 영역·판정 근거를 함께 확인합니다. 전체 파일 SHA-256·원본 프레임 번호·PTS/시간축·픽셀 해시·크기를 확인하며 새 추론·정답 생성·기록 변경은 수행하지 않습니다. 원본 없는 카메라/합성 기록과 이전 기록은 기존 조회를 유지합니다. 순차 디코딩으로 긴 영상 뒷부분의 준비 시간은 남습니다. [사용법과 검증 계약](../guides/RECORD_IMAGE_COMPARISON.md).

## 다중 입력 미리보기 처리 분리 · 2026-10-29

입력별 독립 인코더와 최신 대기 프레임 한 장으로 JPEG 변환을 공통 잠금 밖에서 수행합니다. 느린 입력의 표시 대기가 다른 입력·상태 조회·조작·원본 기록을 막지 않으며, 같은 작업 묶음의 영상/관절/실루엣만 함께 공개합니다. 화질 전환도 잠금 밖에서 준비하고 세대·화질 버전·입력 유효성을 확인해 늦은 결과를 거부합니다. 측정 기록과 판정 기준은 유지합니다. 제어된 변환 지연과 브라우저 회귀 검사는 실제 장치 FPS/지연 향상 측정과 구분합니다. [처리 계약](../design/PREVIEW_CONCURRENCY.md).

## Windows 경로 검사 수정 · 2026-10-29

최신 Actions의 Windows 작업은 242개 중 경로 표현 비교 2개가 실패했습니다. 임시 경로의 `RUNNER~1`과 정규화된 `runneradmin`을 문자열 그대로 비교한 것이 원인이었습니다. 비교 보고서의 누락 경로, 설정 상대 출력 경로와 영상 경로의 예상값을 `Path.resolve()`로 정규화하도록 검사를 수정합니다. 누락 기록 보존·다른 작업 디렉터리에서 설정 상대 경로 해석이라는 검증 목적을 유지합니다. 제품 코드·판정 기준은 변경하지 않습니다. Windows/Linux 재실행 결과는 해당 수정 커밋의 Actions에서 확인합니다.

## 브라우저 미리보기 복구 보완 · 2026-10-29

손상된 JPEG의 브라우저 해독 실패를 표시 오류로 처리하고 상태 조회·측정 조작을 유지합니다. 해당 영상·오버레이를 숨긴 뒤 같은 순번도 1초 간격으로 다시 받아 정지 영상에서 복구합니다. 상태 응답보다 새롭거나 같은 순번의 영상 응답은 자체 해독 결과를 사용하여 이전 `preview_error`가 복구 영상을 지우지 않게 했습니다. 단일/격자 화면에 적용하며 실제 연결 실패 처리는 유지합니다.

재현 가능한 Chromium 검사는 `python tests/browser_preview_recovery.py`로 실행합니다(개발용 Playwright와 Chromium 필요). 생성 영상·SDK 대역을 사용하며 이미지 손상, 같은 프레임 재시도, 지연 상태 응답, 단일/격자 표시와 JavaScript 오류를 검사합니다. GitHub Actions의 Linux 작업에도 연결합니다. 자세 규칙·가중치·0.65 기준·기록 형식은 유지합니다.

## 리뷰 후 안정화와 문서·자동 검사 · 2026-10-29

1단계로 미리보기 JPEG 변환 실패를 `preview_error`로 분리했습니다. 분석·진행 중인 기록은 계속하고 실패 프레임의 영상/오버레이는 숨깁니다. 다음 프레임 또는 정지 파일의 화질 전환으로 복구합니다. 2단계로 README의 현재 기능을 진행 현황에 연결하고 과거 설명을 [구현 이력](IMPLEMENTATION_HISTORY.md)으로 옮겼습니다. GitHub Actions는 Python 3.12의 Ubuntu/Windows에서 합성 입력·SDK 대역 테스트와 wheel 빌드를 수행하도록 구성했습니다. 장치·실제 모델·정답 정확도 검증을 대신하지 않습니다. 자동 검사 실행 결과는 Actions에서 별도 확인합니다.

다음 순서는 카메라 해상도/FPS 요청·실제 수신 정보와 성능 표시, 다중 입력 표시 처리 개선, 원본 영상과 기록 프레임 대조, 실제 자료 평가 후 판정/두 시점 보완입니다. 가중치와 0.65 기준은 유지합니다.

## 미리보기 오류와 측정 분리 · 2026-10-28

미리보기 JPEG 변환 실패는 별도의 `preview_error`로 표시하고 입력·추론·진행 중인 기록을 종료하지 않습니다. 실패 프레임의 이전 영상/오버레이를 재사용하지 않으며 자세와 기록 상태는 계속 갱신합니다. 다음 프레임에서 자동 재시도하고 일시정지 파일은 화질 전환으로 같은 프레임을 재인코딩합니다. 실패 화면에서는 침대 영역 편집과 대상 이미지 선택을 막고 측정 종료/재생 조작은 유지합니다. 입력·추론·기록 자체 오류의 기존 종료 정책과 판정 기준은 유지합니다.

PC에서 영상·측정 조작과 고정 너비의 상태 열을 나누고 영상 높이를 창 높이에 맞춰 제한했습니다. 입력 전 안내와 입력 후 분석 화면을 구분하며 그룹 설정은 오른쪽에 접어 둡니다. 앞선 원본 비율 중심의 틀 확장 방식은 대체하되 영상 전체와 좌표계는 보존합니다. 합성 입력의 40개 창 크기·상태 조합, 설정 접근과 네 점 영역/기록 검사를 브라우저에서 확인했습니다. Windows 실제 장치 확인은 후속입니다. 자세 판정 방식은 변경하지 않았습니다.

## 관절 부족 보류 조건 수정 · 2026-10-28

사용자 보고의 ‘어깨·골반·무릎·발목 좌표 부족’을 확인하고 하체 누락 시 누움 조건의 몸통으로 비교하는 자동 규칙 0.2를 연결했습니다. 앉음/서 있음 구분과 몸통 정보 부족은 보류하고 기존 0.1 기록은 당시 규칙으로 검사합니다. 최근 최대 300개 처리 프레임의 보류 비율·주요 사유를 입력별로 표시합니다. 실제 촬영 조건의 보류율/정확도 개선은 미검증입니다. [조건과 집계 의미](../design/AUTOMATIC_POSTURE.md).

사용자가 수동 기준 등록 없이 자동 판단하도록 요청해 실제 카메라/영상의 기본을 실험용 2D 기하 규칙으로 변경했습니다. 침대 영역 지정 후 바로 누움·옆으로 누움·걸터앉음 또는 보류를 출력합니다. 기본 사선·측면 배치와 위 시점 설정의 차이가 있으며 위 시점은 걸터앉음을 판정하지 않습니다. 임계값·정확도는 아직 미검증입니다. 두 시점은 시간/대상 게이트와 양쪽 라벨 일치로 결합합니다. 기준 등록 화면은 기본 흐름에서 제거하고 이전 기록 호환은 유지합니다. [사용법·가정·한계](../design/AUTOMATIC_POSTURE.md).
