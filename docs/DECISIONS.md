## 합의한 방향

1. 카메라 AI와 외부 ToF·mmWave는 독립적으로 분석합니다.
2. 통제된 침대 환경에서 시작하고 실제 사용 환경 확장은 추후 검토합니다.
3. 실시간 분석과 결과 기록을 수행하며 원본 영상 녹화는 선택할 수 있습니다.
4. 시작 시 녹화 여부를 정하고 분석 중에도 녹화를 시작·중지할 수 있습니다. 녹화 여부와 분석은 분리합니다.
5. 침대 영역은 최초 자동 인식 후 기본 유지합니다. 오류 시 자동 재인식과 사용자 즉시 수동 보정을 지원합니다.
6. 자세·점유 상태·이벤트를 분리하고 이탈 발생·유지·복귀를 추적합니다.
7. 단일 자세와 여러 자세의 순차 계획 측정을 지원합니다.
8. 자동·수동 진행, 자세별 준비 시간, 준비 완료 입력을 모두 지원합니다.
9. 목표 자세·카메라 예측·센서 결과·확인된 실제 정답을 구분합니다.
10. 필요하면 새 자세 분류를 추가할 수 있도록 설계합니다.
11. **2026-10-26 개발 원칙:** 모델은 침대 환경에 대한 인식 품질과 실증 결과를 근거로 선정하며, 코드의 중복 연산 회피·모듈 분리·지연 관리는 개발 과정에서 지속적으로 고려합니다.

자동 침대 인식과 순차 측정은 최종 목표로 유지합니다. 초기 실증에서는 최소 수동 영역 지정과 단순 측정 조작부터 구현할 수 있습니다.

## 2026-10-27 초기 범위와 촬영 조건

**근거:** 프로젝트 기획 검수 후 사용자와 항목별로 확인한 대화. 아래는 카메라 측의 초기 범위이며 외부 센서 개발자와의 합의를 뜻하지 않습니다. 이전 네 자세 후보 중 ‘일어남’은 침대 이탈을 의미하는 것으로 정리하고 자세와 이벤트를 분리합니다.

| 항목 | 현재 기준 | 근거·남은 조건 |
|---|---|---|
| 초기 자세 — 합의 | 바로 누움·옆으로 누움·걸터앉음 | 사용자 “일단 세가지로만”; 좌우 세분화·엎드림 보류. 주석용 자세 경계는 미정 |
| 움직임 — 합의 | 세 자세 사이의 변화와 침대 이탈·복귀 | 사용자 “1번”; 같은 자세에서 팔·다리만 움직이는 동작은 후속 검토 |
| 이탈 완료 — 합의 | 침대에서 내려와 완전히 서 있는 시점 | 사용자가 직접 지정. 걸터앉아 발만 바닥에 둔 상태는 완료 전. 시각적 판별 규칙·확인 시간·이탈 시작은 미정 |
| 복귀 — 운영 해석 | 다시 걸터앉으면 복귀로 보는 방향 | 걸터앉음/누움 중 복귀 기준을 묻자 사용자 “복귀”; 이를 걸터앉으면 복귀로 해석하여 대화를 진행함. 바로 올라가 눕는 경로 포함은 제안이며 세부 완료 경계는 추가 정리 필요 |

| 주변 인물 — 환경 조건 | 가끔 여러 사람이 화면에 나올 수 있음 | 사용자 설명. 측정 대상 한 명 선택·추적은 아래 설계 제안 |

완전히 서지 않는 침대 밖 이동 등 현재 완료 정의에 포함되지 않는 동작의 처리와, 영상에서 완료 조건을 확인할 수 없는 구간의 주석 기준은 아직 정하지 않았습니다. 미확인 상태를 ‘침대에 있음’으로 자동 대체하지 않습니다.

## 검토 중인 운영·판정 설계

다음은 AI가 제안한 설계이며 개별 정책·임계값의 사용자 확정이나 구현·성능 검증 완료를 뜻하지 않습니다.

- 한 번에 한 명을 측정 대상으로 선택하고 다른 사람의 등장·겹침을 처리합니다. 대상 불확실 시 판정을 보류하며, 복구 또는 재선택 방법을 검토합니다. 여러 사람 동시 측정은 별도 범위 제안입니다.
- 세션마다 침대 영역·화각을 확인하고 촬영 배치를 기록합니다. 카메라 이동 시 침대 관계가 필요한 판정을 보류하고 영역을 다시 확인합니다.
- 자세와 별도로 **안정 / 변화 후보 / 판정 보류**를 관리합니다. 보류 중 마지막 확인 자세를 현재 자세로 표시하지 않습니다.
- 품질이 유효한 관측으로 후보를 확인한 뒤 변화·이탈·복귀를 한 번 기록합니다. 관측 공백으로 이벤트를 지어내거나 초기 상태를 새 이벤트로 처리하지 않습니다.
- 완료 추정 시각·판정 확정 시각·결과 출력 시각을 구분합니다. 자세·이벤트 확인 시간과 품질 임계값은 검증 자료로 결정합니다.

상세 흐름은 [시스템 구조](ARCHITECTURE.md), 사례는 [측정 절차](MEASUREMENT_PROTOCOL.md)에 기록합니다.

## 잠정 비교 목적과 실험 방식

**실험 방식:** 사전 계획한 자세·동작을 순서대로 수행하는 방식이 유력합니다. 자유 측정도 지원하며 실제 순서·반복 횟수는 미정입니다.

## 기술 비교 제안 — 아직 미선정

MediaPipe Pose Landmarker·YOLO Pose·RTMPose를 같은 저장 영상에서 우선 비교하고 MoveNet을 경량 대안으로 유지합니다. 단순 자세 분류와 상태 전이 기준선을 먼저 만들고, 실험 결과에 따라 LSTM/TCN·그래프 모델 등을 검토합니다.

MediaPipe의 추가 기능 활용과 MediaPipe Pose Landmarker·YOLO Pose/RTMPose 병용은 추가 검토 후보입니다. 확인된 내용은 활용 가능성에 대한 질문이며, 구체적인 결합 구조나 채택 결정은 확인되지 않았습니다. 기존의 동일 영상·독립 후보 비교 계획을 유지하고, 누운 자세의 인식 우열이나 병용 효과를 실험 없이 확정하지 않습니다.

세부 후보는 [기술 후보 비교](TECHNOLOGY_CANDIDATES.md), [실험 계획](POSE_BENCHMARK_PLAN.md), 실행 순서는 [로드맵](../ROADMAP.md)에서 관리합니다. 문헌 조사만으로 모델을 채택하거나 성능을 확정하지 않습니다.

## 2026-10-27 구현 우선 순서 조정

**사용자 요청·승인:** “미리 구현을 거의 다 진행하고나서 학습”, 이어서 “좋아 구현하자”. 추가 샘플의 수작업 점수 비교는 잠시 보류하고, 학습/튜닝보다 기능 경로 연결을 우선합니다. 현재까지 별도 모델 학습은 수행하지 않았습니다.

첫 범위는 카메라 입력·스켈레톤 표시·수동 침대 영역·측정 시작/종료·기록입니다. 입력·상태·시각·기록·실패 처리의 개발 검사는 병행하며, 미구현 자세/이벤트 판정을 실제 예측처럼 표시하지 않습니다. 모델 성능에 의존하는 판단은 분리해 후속 학습/검증으로 조정합니다. 자동 침대 인식·선택적 녹화·자유/계획 측정 등 기존 합의 목표를 삭제한 것은 아닙니다.

표준 Tk 창과 기존 MediaPipe 의존성의 OpenCV 재사용은 이번 최소 구현의 선택이며 최종 UI/추론 플랫폼 확정이 아닙니다. 실시간 기록 형식 live-0.1-draft는 초기 구현 계약으로, 장기 저장·센서/정답 교환 사양을 확정한 것이 아닙니다.


## 입력 선택·화면 개선 요청 · 2026-10-27

사용자는 UI/UX 개선, 휴대폰/외장 카메라 및 복수 카메라 상황을 고려한 입력 선택, 기존 촬영 영상 활용, 직관적 자세 판정 표시를 요청했습니다. 카메라 번호 선택/확인·파일 열기·입력별 독립 탭과 상태 카드를 구현합니다. 휴대폰은 OS에서 웹캠으로 인식되는 조건이며 별도 휴대폰 앱/전송 프로토콜은 이번 범위가 아닙니다. 다중 입력 실행은 동기화·융합·통합 대상 추적의 완료를 의미하지 않습니다.

자세 카드에는 분류기 미연결을 명시하고 관절 후보를 자세명·정확도로 바꾸지 않습니다. 파일은 원본 PTS 기준, UI 수신/조작은 입력별 단조시계 기준으로 구분합니다. 기존 live-0.1 기록 검증을 유지하며 파일용 필드를 추가한 live-0.2-draft는 임시 내부 형식입니다.


## 기본 화면을 HTML로 전환 · 2026-10-27

사용자는 Tk UI/UX를 거부하고 기존 HTML 검토 화면과 같은 브라우저 실행 방식을 요청했습니다. `live` 기본 진입을 로컬 HTML 작업실로 바꾸며 Tk는 기본 실행에 사용하지 않습니다. 저장 결과 HTML과 달리 실시간 제어에는 같은 PC에서 Python 서버 실행이 필요합니다. 표준 HTTP 서버와 기존 추론/기록 엔진을 재사용하며 외부 호스팅·새 웹 프레임워크·휴대폰 원격 제어를 도입하지 않습니다. 브라우저에서 고른 원본 파일/모델은 로컬 임시 복사 후 분석하며 정상 종료 시 정리합니다. 현재 자세/이벤트 미구현 상태와 학습 전 기능 연결 방침은 유지합니다.
