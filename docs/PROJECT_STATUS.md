## 검증 상태

- 개발 환경에서 생성 영상·SDK 대역·오류/변조·기록 재계산·브라우저 동작을 검사했습니다.
- 이전 기능 커밋 [a5ee480](https://github.com/zntks1234/bed-pose-skeleton-ai/commit/a5ee4803eae61bb9cdc807c98e47ef60ced32266)의 [GitHub Actions](https://github.com/zntks1234/bed-pose-skeleton-ai/actions/runs/40798135896)는 Windows/Linux 테스트·빌드와 Linux 브라우저 검사를 통과했습니다.
- 2026-10-29 분리 구현은 Linux에서 전체 265개 개발 검사와 관련 후속 검사, 기존 브라우저 검사 2종·새 분리 브라우저 검사, 패키지 빌드를 확인했습니다. 생성 입력·SDK 대역 검사이며 실제 자세 정확도 검증은 아닙니다.
- 분리 커밋 c3128e3의 Actions는 Windows 통과·Linux 실패였습니다. 미리보기 치수 공개 전 FPS만 기다리던 테스트의 비동기 경쟁을 수정했습니다. 독립 영상 근거 연결·평가 도구의 최신 검사 결과는 해당 후속 커밋의 Actions를 기준으로 확인합니다.
- CLIP 라이브러리 설치/가져오기와 작은 무작위 가중치의 실제 Transformers CLIP 로딩·문장 캐시·이미지 추론을 확인했습니다. 연결·기록·브라우저는 명시적 대역으로 검사합니다. Hugging Face 다운로드는 프록시 403으로 차단돼 사전학습 가중치·첨부 마네킹·실제 사람의 CLIP 결과를 확인하지 못했습니다.
- 사용자 Windows PC의 실제 모델 실행과 일부 프레임 육안 검토 보고가 있습니다. 통제된 실제 장치 성능 시험과 구분합니다.
- 실제 사람의 관절 정확도·자세별 Precision/Recall/F1·보류율·전환 지연·다중 카메라 종단 지연은 아직 검증되지 않았습니다.
- 문헌 37편 중 P11·P12·P19·P34는 본문 미확인입니다. P35의 2022 ACM 최종판도 본문 미확인이고, 확인된 공개 판본의 근거만 사용합니다. [문헌 확인 범위](research/LITERATURE_REVIEW.md).

테스트 수는 변경되므로 이 문서에서 매번 누적하지 않습니다. 특정 실행의 결과는 해당 커밋의 Actions를 확인합니다. 기록 검사 통과를 자세 정확도나 실제 노출 프레임의 완전 수신으로 해석하지 않습니다.

## 카메라 단독 동작 보완 · 2026-10-30

CLIP 제공자 0.2는 신뢰도와 어깨·골반·하체 최소 관측을 검사하고 입력 영역/보류 사유를 기록합니다. 초기 품질 정책이며 전신 포함·정확도를 보장하지 않습니다. 이미지 제공자 오류는 관절 처리 성공과 분리해 표시/기록합니다. 추적은 측정한 직전 프레임 처리 시간을 관측 공백에서 구분하며, 미검출·다인 혼동은 계속 재지정을 요구합니다. 실루엣은 기본 비활성화했습니다. 실제 카메라 속도·인식 성능 검증은 남아 있습니다.

## 처리 자원·표시 개선 · 2026-10-30

CLIP 실행 장치는 기본 자동 선택(CUDA 지원 시 CUDA, 아니면 CPU)하며 CPU 연산 스레드의 기본 상한을 4로 제한합니다. 입력별 읽기·관절·이미지 처리 시간을 표시하고 실험 기록에 실제 CLIP 실행 설정을 남깁니다. 긴 상태 설명으로 형태 적합도 제목이 압축되던 열 배치를 수정했습니다. 실제 PC의 FPS 개선은 미검증이며 [속도 확인 방법](guides/LIVE_MEASUREMENT.md#처리-속도-확인과-실행-장치)을 따릅니다.

## 다음 단계

CLIP 사전학습 자산을 준비하고 마네킹/별도 검토한 사람 자료에서 실제 결과를 평가합니다. CLIP 실행 제공자는 구현했으며, 자산 준비·CLIP 선택 시 0.8이고 미사용 시 0.7입니다. 같은 자료의 SigLIP 2 비교와 최종 모델 선정은 후속입니다. 실제 영상에서는 한 명·한 카메라·이불 없는 세 자세 유지/전환과 서 있음 등 범위 밖 동작을 별도 주석으로 평가합니다. 이후 시점·가림·주변 인물·두 카메라로 넓힙니다. 순서와 완료 기준은 [로드맵](../ROADMAP.md)에서 관리합니다.

## 수신 분리·재검사 보완 · 2026-10-30

실제 카메라의 최신 프레임 수신 작업과 분석을 분리하고 개별 최신 영상/분석 프레임 전환을 구현했습니다. 저장 영상·여러 화면 격자는 순차 분석/분석 프레임 표시를 유지합니다. 분석하지 않은 수신 프레임 수를 기록하며 물리 장치 유실과 구분합니다. CLIP 입력 확인 PNG는 브라우저 근거 창 사용 여부에 따라 생성합니다. 제공된 Windows 309프레임 기록은 float 재계산 허용 오차 보완 후 Linux에서 무결성 재검사를 통과했습니다. 실제 카메라의 표시 FPS 개선·장시간·다중 장치 성능 검증은 남아 있습니다.

## 동시 수신 기록 종료 검증 수정 · 2026-10-30

수신 분리 후 기존 시간 검사에서 정상적인 프레임 간 수신/분석 겹침을 거부하던 오류를 수정했습니다. 겹침을 재현한 새 측정은 정상 종료·해시 재검사를 통과하고 시각 역행/분석 순서 오류는 계속 거부합니다. 사용자 379프레임 기록의 내용 검사는 통과했지만 원본의 실패/미완료 표시와 누락된 해시는 변경하지 않았습니다. 실제 장치에서 수정 후 새 측정의 종료 검증이 필요합니다.

## 인식 확인 화면 보완 · 2026-10-30

카메라 기본 화면을 관절·침대 영역이 표시되는 분석 프레임으로 변경했습니다. 표시 전환 버튼은 영상 상단에 배치하고 최신 영상만 모드에서는 관절 표시 조작을 비활성화해 실제 표시와 설정이 어긋나지 않게 했습니다. 수신/분석 분리 구조는 유지합니다.

## 최신 영상의 침대 영역 · 2026-10-30

최신 수신 영상에도 지정한 침대 경계와 모서리 번호를 표시합니다. 분석 프레임과 동일한 원본 좌표를 영상 비율·여백에 맞춰 변환하고, 영역 해제/입력 변경/크기 불일치 시 숨깁니다. 관절은 분석 프레임에서만 표시합니다.

## 표시·전송 경량화 · 2026-10-30

미사용 최신 영상 인코딩의 요청 기반 실행, 상태가 같은 응답의 304 처리·canvas 재그리기 생략, 고정 모델 설정의 브라우저 캐시를 구현했습니다. 전체 상태 API·기록 형식·모델 입력과 판정 계산은 유지합니다. 최신 영상 요청 중단/재개·화질 변경, 고정 설정 갱신/응답 분리, 변경 상태 전송을 모의 검사하며 실제 장치의 자원 절감 폭은 별도 확인합니다.
