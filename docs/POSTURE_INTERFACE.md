# 자세 판정 인터페이스와 현재 관측 상태

2026-10-28. 사용자 요청에 따라 순차 측정을 후순위로 두고 자세 확인 경로를 우선한다. 이번 구현은 **프레임별 분류 입출력·보류 사유·화면/기록 연결**이다. 실제 3자세 분류 방법·학습 가중치는 아직 연결하지 않았다. 따라서 현재 실행에서 자세명 예측은 생성하지 않는다.

## 화면

오른쪽 카드에 입력 대기, 관측 중단, 판정 보류, 판정 대기를 표시한다. 미검출, 여러 후보, 추적 보류, 화면 내 좌표 없음, 분류기 미연결을 구분한다. 프레임 번호·화면 내 좌표 수·침대 영역 유무를 표시하며, 좌표 수를 정확도나 분류 가능성으로 해석하지 않는다. 합성 입력은 실제 인체 판정이 아님을 표시한다. 입력 종료/오류 시 이전 자세를 현재 자세로 표시하지 않는다.

‘두 시점 판정 상태’에는 선택 입력이 속한 최근 그룹과 양쪽 입력의 프레임/관절 상태를 보여준다. 두 최신 미리보기는 동시 촬영/시간 정렬된 쌍이 아니므로 통합 판정을 만들지 않는다. 완료 그룹의 프레임별 정렬 자료와 현재 미리보기 상태도 구별한다. 실시간 페어링·통합 분류기 연결은 후속 작업이다.

## 모듈 계약

`posture.py`의 `PostureClassifier.predict(PostureInput)`는 supine/side/edge_sitting 또는 None(기권)을 반환하는 확장 지점이다. 현재 앱은 분류기 없이 호출한다. 테스트에서만 모의 분류기를 넣어 경로를 검사한다. 모델 선택·로드 UI나 임의 각도 규칙은 추가하지 않았다.

입력은 해당 후보의 화면 내 유한한 좌표(나머지 None), 영상 크기, 선택적 침대 사각형뿐이다. 목표·정답·센서·파일명은 전달하지 않는다. 좌표 (0,y)도 유효하며 점수 임계값·보간·시간 평활화는 적용하지 않는다. 작업별 관절 충분성이나 범위 밖 자세 처리는 실제 분류기를 선정할 때 별도 검증해야 한다. 화면 내 좌표 하나가 있다는 것만으로 분류 정보가 충분하다고 보증하지 않는다.

대상 추적이 설정되면 해당 후보만 사용한다. 추적 보류 시 다른 후보로 바꾸지 않는다. 추적 미설정의 단일 후보는 잠정 관측이며 동일인 연속성 검증이 아니다. 여러 후보/후보 없음/처리 실패는 보류한다. 분류기의 None, 잘못된 라벨, 예외도 명시적으로 보류하며 직전 라벨을 유지하지 않는다. 모델 지연·시간 안정화·확률 보정은 미구현이다.

## 기록과 호환성

원본 live 프레임에 `posture_assessment`를 추가하고 manifest에 `posture_assessment_profile`을 기록한다. 프레임 ID/시계/수신 시각, 상태·사유·후보/추적 ID, 좌표 수·영역 유무·분류기 ID를 포함한다. 기본 앱의 상태는 unavailable/held, label=null이다. 기존 posture_prediction은 not_implemented/null, 목표·정답·센서 필드는 그대로 유지한다.

live-inspect는 프로필과 프레임 관측으로 기본 판정 상태를 재계산해 대조한다. 프로필이 있는 새 기록의 필드 누락도 거부한다. 필드/프로필이 없는 기존 live-0.1/0.2 기록은 계속 검사한다. 실제 분류기를 앱에 연결하려면 프로필·예측 기록 계약·검사기도 함께 확장해야 하며, 모의 분류기의 출력만으로 제품 예측을 활성화하지 않는다.

## 다음 실증

누움/옆누움/걸터앉음과 서 있음 등 범위 밖 사례를 별도 정답으로 확인한 소규모 영상에서 정보 충분성·기권을 검증한다. 특히 투영·가림에 따른 바로 누움/옆누움 구분 가능성을 먼저 확인하고, 이를 근거로 분류 방식과 두 시점 결합 기준선을 정한다. 목표 자세를 학습 정답으로 대체하지 않는다.
