# 원본 프레임과 저장 결과 대조 · 2026-10-29

[기록 조회](RECORD_BROWSER.md) · [시간축](RECORD_TIMELINE.md) · [진행 현황](PROJECT_STATUS.md)

## 사용법과 지원 범위

측정 기록 보기 → 완료된 영상 파일 기록 선택 → 원본 프레임 대조에서 측정에 사용한 영상 선택 → 표의 프레임 번호 버튼. 시간축의 프레임 이동도 대조 패널에 연결한다. 선택 영상은 기존 업로드 API로 로컬 임시 복사하고 작업실 종료 시 정리한다. 기록에 저장된 경로로 임의 파일을 자동으로 열지 않는다. 카메라 없이 조회할 수 있으며 라이브 측정은 별도로 계속된다.

기록 프레임 번호와 입력 스트림 프레임 번호, 원본 디코딩 프레임 번호는 구분한다. 첫 프레임 미리보기 뒤 측정을 시작하면 첫 기록 프레임은 원본 0번이 아닐 수 있다. 수신 경과로 영상 시점을 추정하거나 FPS로 프레임을 역산하지 않는다.

## 대응 검증

인증된 POST `/api/records/image`는 `record_id`, 정수 `frame_id`, 기존 영상 업로드의 `video_asset`을 받는다. 먼저 열린 검증 기록만 지원하고 자산 ID를 통해서만 원본을 읽는다. API가 받은 경로나 기록 속 원본 경로를 파일 접근에 사용하지 않는다.

기록 원본 해시를 전후 검사한다. 같은 VideoFileSource의 정규 RGB/회전/PTS 정책으로 원본 파일을 순차 디코딩한다. 전체 영상 SHA-256이 측정 당시와 같고, 해당 원본 프레임의 PTS·time base·상대 PTS 시각·픽셀 해시·원본 번호와 실제 크기가 저장값과 일치할 때만 표시한다. 디코더 차이로 픽셀이 달라도 대조를 보류한다. 잘린 영상이나 재인코딩본은 같은 장면이어도 원본으로 인정하지 않는다. 디코딩 종료 시 영상 파일 변경도 검사한다.

영상은 기존 고화질 JPEG 설정으로 전달한다. 픽셀 해시는 JPEG 압축 전 정규 RGB에 대한 확인이며 브라우저 영상이 무손실이라는 의미는 아니다. 저장된 관절과 그 프레임의 영역 revision에 대응하는 침대 경계를 같은 좌표 변환으로 그린다. 저장된 자세/가중 근거·실루엣 보조 상태는 접이식 상세에 그대로 표시한다. 전체 실루엣 마스크는 기록되지 않아 복원하거나 새 추론으로 채우지 않는다.

## 실패와 자원

원본이 없어도 목록·표·시간축 조회를 유지한다. 카메라/합성 입력, 원본 정보 없는 이전 기록, 빈 기록에서는 원본 대조를 제공하지 않는다. 선택 변경·페이지 이동·기록 전환·창 닫기 뒤 도착한 이전 응답은 UI 세대로 거부하며, 영상 준비 오류는 기록 조회나 라이브 연결 종료로 처리하지 않는다.

같은 열린 기록의 디코딩은 직렬화하고 전체 프레임 배열은 보관하지 않는다. 매 요청은 파일 해시와 시작부터의 순차 디코딩을 수행하므로 큰 영상의 뒷부분은 느릴 수 있다. 빠른 임의 탐색·원본 영상 녹화·연속 재생·정답 주석·유지 시간/정확도 계산은 후속 범위이다. 프레임 대응 검증은 저장된 관절/자세의 정확도 검증과 별개이다.

## 개발 검사

생성 FFV1 영상과 SDK 대역으로 측정 시작 전 프레임과 기록 프레임의 번호 차이, 첫/끝 프레임의 PTS/픽셀 대응, 저장 근거 보존, 무추론·기록 해시 불변, 잘못된 원본/번호/자산/인증/변경 기록 거부를 확인한다. 원본 없는 기록은 조회가 계속되는지 검사한다. Chromium에서 원본 선택·프레임 선택·근거 상세·좁은/넓은 화면·창 닫기를 확인한다. 실제 사람의 자세 성능을 검증한 결과는 아니다.
