# 기능 요구사항 및 개발 우선순위 (v0.2)

**표기 원칙:** '합의한 목표 기능'과 '현재 구현된 기능'은 다릅니다. 현재 구현된 기능은 없습니다. 우선순위는 최초 구현 순서를 뜻하며 기능 취소를 뜻하지 않습니다.

## P0 · 핵심 측정 및 2차 교차 검증

| ID | 요구사항 | 수용 관점(초안) |
|---|---|---|
| CORE-01 | 카메라 영상에서 실시간 스켈레톤 추정 | 촬영 시각과 함께 관절 결과 확인 가능 |
| CORE-02 | 스켈레톤 기반 AI가 독립적으로 자세 분류 | 목표 자세/센서 결과를 모델 입력으로 누설하지 않음 |
| CORE-03 | 기본 자세 분류 후보 수용 | 누움, 옆으로 누움, 걸터앉음, 일어남(이탈); 최종 라벨 협의 |
| CORE-04 | 변화·이탈·복귀 이벤트 감지 | 이벤트 시작/상태/복귀 기준을 추후 합의 |
| CORE-05 | 미검출·모호 상태 구분 | 화면 밖 이동을 곧바로 이탈 정답으로 처리하지 않음 |
| CORE-06 | 시간별 예측 및 이벤트 저장 | 동일 실험 식별자와 프레임/시각 관계 보존 |
| CORE-07 | 외부 센서와 결과 비교 | 공통 라벨·시각 정렬 후 일치/불일치/판정 불가 비교 |
| CORE-08 | 최소 실험 타깃 지정·확인 | 사전 계획 자세와 실제 확인된 자세를 분리 |

## P1 · 합의한 운영 기능 (단계적으로 구현)

- 침대 영역을 분석 시작 시 **자동 인식**, 이후 기본 유지. 오류 발생 또는 사용자 요청 시 **자동 재인식**, 언제든 **즉시 수동 수정**. 수정 시각과 불확실 구간 기록.
- 선택적 원본 영상 녹화: 프로그램 시작 시 녹화 여부 확인, 분석 중 녹화 시작·중지, 여러 녹화 구간 관리. 녹화가 꺼져도 실시간 분석과 분석 데이터 기록 지속.
- 실시간 화면: 카메라 영상, 스켈레톤, 현재 자세, 침대 경계/점유, 이탈·복귀 이벤트, 녹화 상태 및 영역 수정 제어.
- 단일 자세 계획 측정 및 여러 자세 순차 측정.
- 자동(시간 기반)·수동 진행과 상호 전환, 자세별 준비 시간 설정 및 '준비 완료' 확인, 일시정지·재개·재측정.
- 평가를 위한 자세 유지 구간과 움직임·전환 구간을 목적에 맞게 구분. 이탈/복귀 시 전환 동작 자체를 기록.

> 구현 순서는 필수 기능을 검증한 후 P1 운영 기능을 순차적으로 완성하는 것을 권장. 초기 실증에서는 침대 영역을 임시로 수동 지정해 AI 검증을 먼저 수행할 수 있으며, **자동 인식 목표를 폐기하는 것은 아님**.

## P2 · 미확정 또는 추가 검토

- 스마트폰 브라우저 원격 조작, 모바일 AI 결과 표시/숨김, PC/모바일 역할 분담
- 사후 영상 재생·정답 시간 보정 UI
- 좌/우 측면 등 추가 자세 세분화, 이불·신체 가림 대응
- 카메라 위치 변화/실사용 환경 확대의 고도화

## 아직 정해야 할 성능·환경 제약

- 실험장 배치 및 카메라 종류·설치 각도/높이/화각, PC 처리 환경
- 실시간 처리 주기와 최대 허용 지연, 인식/이벤트 평가 기준
- 외부 센서 제공 데이터(원시 값/분류 결과) 및 수신 방식
- 사용 인원/촬영 동의/데이터 보관 기간
- 학습 데이터량, 모델 선정 기준, 프레임 저장 주기

## 비기능 원칙

- 카메라 AI와 센서는 서로의 예측을 입력받아 정답을 맞추지 않음
- 계획 라벨과 독립적으로 확인된 정답 라벨의 출처/상태를 분리
- 잘못된 침대 경계나 영상 미검출 시 과신하지 않음
- 측정 반복 가능성, 시간 동기화 및 민감 데이터 보호를 중시
